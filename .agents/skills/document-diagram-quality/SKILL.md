# 문서 다이어그램 품질

그림의 문서 내 실제 크기에서 글자와 연결 관계가 읽히도록 개선한다. 새 내용을 기획하는 작업과 기존 도식의 충실한 재구성을 구분한다. 파일 형식별 편집·검증은 해당 문서 스킬을 함께 따른다. HWPX 패키지·양식 보존에는 `$hwpx-authoring`을 사용한다.

## 대상과 보존 범위

현재 문서와 원자산의 SHA, 그림 소유 위치·캡션·절 귀속, 연결된 자산을 기록한다. HWPX에서는 OPF spine 순서와 그림 owner XPath·binItem 참조를 확인한다. 개선 대상과 보호할 나머지 그림을 구분하고 원본은 읽기 전용으로 둔다.

요청한 변경 범위를 먼저 구체화한다.

- 원자산 교체만 허용되면 기존 앵커·슬롯·표/셀 구조·캡션·절 귀속을 보호한다. 비율이 다른 그림을 슬롯에 억지로 늘리지 않는다. 비율 유지 배치의 여백과 가독성 한계를 확인한다.
- 그림 크기·비율 조정이 포함되면 필요한 폭/높이·잘라보기·둘러싸기 변경을 선언한다. 이 권한을 표 재설계, 항목 이동, 제목/본문 수정으로 확대하지 않는다.
- 내부 여백 정리가 포함되어도 범례·연결선·그룹 경계·입력칸·설명 고지·의미 있는 레인 간격을 함께 삭제하지 않는다. 표로 만든 도식의 빈 셀은 배치용일 수 있다.

## 진단: 세 가지 공간을 분리

그림 캔버스의 외곽 공백, 문단·셀·개체의 바깥 여백, 도식 내부의 의미 있는 공간을 따로 확인한다. 픽셀의 비백색 경계만으로 내부 공간의 필요성을 판정하지 않는다.

원본 픽셀 크기와 문서에서 보이는 크기를 대조한다. DPI 메타데이터를 실효해상도로 대신하지 않는다.

```text
ppi_x = visible_source_pixels_x / (display_width_mm / 25.4)
ppi_y = visible_source_pixels_y / (display_height_mm / 25.4)
relative_x_to_y_scale = (display_width_mm / pixels_x) / (display_height_mm / pixels_y)
```

위 계산은 해당 픽셀 영역이 표시 사각형에 실제 매핑되는 경우에만 유효하다. crop, 회전, 원근/행렬변환, 중첩 개체가 있으면 그 관계를 먼저 해결한다. HWPX의 orgSz·curSz·sz 한 쌍만 보고 왜곡이라고 단정하지 않는다. 해석하지 못한 변환은 `unknown`으로 남긴다. 고해상도로 저장하거나 픽셀을 늘린 사실은 원정보 회복이 아니다.

필요하면 읽기 전용 감사 도구를 사용한다. 스크립트 경로는 읽은 이 SKILL.md의 디렉터리를 기준으로 해결한다. Pillow가 필요하며 이미지와 패키지를 수정하지 않고 JSON만 만든다. 문서 XML이나 crop/변환을 자동 해석하지 않는다.

```sh
python scripts/audit_picture.py IMAGE --width-mm WIDTH --height-mm HEIGHT --mapping stretch --report PRIVATE_REPORT.json
```

검증한 source viewport가 있으면 `--crop-box LEFT TOP RIGHT BOTTOM`을 픽셀 좌표로 지정한다(오른쪽·아래 경계 제외). `stretch`는 그 viewport가 박스 전체를 채우는 경우, `contain`은 비율을 유지해 박스 안에 들어가는 경우다. 매핑을 모르면 기본 `unknown`을 유지한다. `--help`에 옵션과 한계가 있다.

매핑을 확정할 때는 원장에 `source_viewport_px`, `display_mm`, `mapping`, `mapping_evidence`, `unresolved_transforms`를 함께 적는다. `mapping_evidence`에는 실제 crop·이미지 좌표·배율/회전과 native 관찰의 일치 근거를 적고 파일 확장자나 단일 크기쌍으로 대신하지 않는다. 예를 들어 세로 원본 800×1200px을 고정 160×60mm 슬롯에 contain하면 그림은 40×60mm이므로 좌우 공백이 크게 남는다. 크기 변경 권한이 있으면 높이를 확보하고, 없으면 고정 슬롯에서 얻을 수 있는 가독성 한계를 명시한다.

Windows에서 `python`이 Store 별칭이면 이를 반복 실행하지 않는다. 현재 앱의 `load_workspace_dependencies` 또는 확인된 프로젝트 환경에서 Python과 Pillow의 실제 경로를 찾고 그 경로로 실행한다. 로컬 개인 절대 경로를 스킬 원문에 고정하지 않는다.

보고서의 공백 경계는 배경색·색차 허용값에 따른 **외곽 여백 후보**다. 연한 선·안티앨리어싱·투명도와 흰 내용에 민감하며 자동 자르기 권한이 아니다. PPI가 높아도 작은 라벨과 큰 내부 공백 때문에 읽기 어려울 수 있다. 고정 PPI·공백 비율·폰트 크기를 모든 문서의 합격선으로 강제하지 않는다.

## 원본 우선으로 개선 경로 선택

제공된 자료와 작업공간에서 실제 편집 원본(SVG, 도형이 살아 있는 슬라이드/드로잉 등), 원벡터, 원고해상도 자산을 먼저 찾는다. 비슷한 그림이 아니라 같은 버전·범위·값·관계인지 대조한다.

1. 편집 가능한 원본이 있으면 원본에서 캔버스·배치를 정리하고 종횡비를 유지해 다시 내보낸다. 단순 비율 오류라면 올바른 표시 비율을 복원하는 것으로 충분할 수 있다.
2. 더 나은 원자산이 있으면 원자산을 교체한다. 래스터화가 필요한 문서 형식에서는 최종 표시 크기와 실제 글자·선의 가독성을 기준으로 출력 크기를 선택한다. SVG가 있다는 사실만으로 문서나 PDF가 벡터를 유지한다고 주장하지 않는다.
3. 적절한 원본이 없고 도식의 의미를 확인할 수 있으면, 아래 의미 원장을 만든 뒤 코드 기반 SVG/벡터로 충실히 재구성한다. 눈에 보이지 않거나 모호한 라벨·화살표를 추측해 완성하지 않는다. 사진·증빙 화면을 임의의 깔끔한 도식으로 바꾸지 않는다.

기존 래스터를 실제로 자르거나 보정·변형하는 편집은 환경의 `imagegen` 지침을 따른다. 이 감사 스크립트를 이미지 편집기로 확장하거나 Python으로 편집 결과 이미지를 만들지 않는다. 원벡터의 편집·재출력과 확인된 의미를 바탕으로 새 SVG를 작성하는 경로는 래스터 픽셀 편집과 구별한다.

## 재구성할 때 확인할 의미

재구성 전에 라벨 원문, 수치·단위·상태·연도/단계, 노드·그룹·범례, 연결의 출발/도착·방향·분기, 색/선의 의미, 출처·예시/미확인 고지를 대조 가능한 원장으로 정리한다. OCR은 초안이며 원이미지와 확인한다. 연결선이 교차하는 것과 접속하는 것을 구분한다.

새 벡터는 라벨과 관계가 분리된 편집 가능한 객체로 작성한다. 긴 라벨의 줄바꿈, 그룹 안팎 위치, 화살촉과 선의 구분을 실제 표시 크기에서 확인한다. 디자인 개선을 이유로 내용 축약·명칭 통일·연결 변경·수치 보정·권한/계획의 확정을 하지 않는다. 필요한 내용 변경은 별도 근거와 허용 범위로 다룬다.

극소 원문 일부를 판독할 수 없으면 새 글자를 추측해 선명하게 만들지 않는다. 원문을 그대로 남긴 혼합 도식 등 의미 손실 없는 대안을 선택하고, 남겨 둔 래스터 영역과 판독 한계를 기록한다. 새 SVG 안에 저해상도 이미지가 들어 있으면 전체 PNG의 높은 PPI를 그 영역의 원정보 해상도로 주장하지 않는다.

검사에서 라벨 개수만 세지 않는다. 각 라벨/값의 대상, 그룹 소속과 edge 목록을 전후 대응시킨다. 벡터 소스의 텍스트가 맞아도 내보내기에서 글꼴 누락·글자 잘림이 생길 수 있으므로 실제 출력까지 확인한다.

## 문서 반영과 완료

변경 전후의 자산·문서 SHA, 소유 위치, 표시 크기·비율·crop/변환, 바뀐 속성과 보호 대상을 기록한다. 실제 사업의 원자산·라벨·관측과 개인 경로가 포함된 보고서는 비공개 작업공간에 둔다. 대상 외의 본문·제목·표 구조·그림·서명/필드 등은 해당 문서의 보존 검사로 확인한다. 더 나은 가독성을 얻었다는 이유로 사용자 양식의 구조 변경을 묵인하지 않는다.

현재 최종 바이트를 해당 문서의 네이티브 앱에서 열고 저장/내보낸 결과를 검토한다. 실제 앱 버전과 현재 HWPX/DOCX/PPTX·PDF·페이지 이미지의 SHA를 연결한다. 결과 전체 페이지에서 흐름 변화를 확인하고, 그림 페이지는 원페이지와 확대 보기로 라벨·수치·연결선·그룹·범례·글꼴 대체·선 굵기·캡션·앞뒤 내용의 잘림/겹침을 직접 확인한다. 한 그림을 확인할 때는 원페이지를 단독으로 열어 표시 결과의 혼동을 줄인다.

구조·의미 대응 검사, 픽셀 감사 수치, 네이티브 시각 검토를 별도 결과로 보고한다. 현재 결과에 네이티브 QA를 하지 못했다면 그 범위를 명시하고 최종 페이지 품질 합격을 주장하지 않는다. 산출물과 원벡터/코드, 감사 보고서, 현재 출력과 검토 범위·남은 문제를 함께 전달한다.
