# 참고자료를 활용한 업무 표현과 편집

정상적인 HWPX 패키지, 의미 보존, 읽기 좋은 편집, 실제 사업의 자료 충족 여부를 각각 판단한다. 현재 구현과 프로필 상태는 helper `path`로 찾은 repo의 `docs/GENERATION.md`, `docs/REFERENCE_QUALITY_UPGRADE.md`, `resources/style-upgrade/profiles/index.json`에서 확인한다. 프로필이 `candidate_unvalidated`면 이미 검증된 모범 규칙으로 보고하지 않는다.

## 프로필 선택

같은 문서 역할·양식 SHA에 연결된 프로필을 선택한다. `generate ... --style-profile reference-v1`은 역할별 서식과 업무 표현을 적용하는 명시적 선택이다. 옵션을 생략한 보존 모드와 의도한 서식 변경 범위를 혼동하지 않는다. 임의 양식에 기존 역할 프로필을 적용하거나 원본의 숫자형 서식 ID를 복사하지 않는다.

채택값과 관찰값을 구분한다. 참고자료에 있다는 이유로 극단적인 여백·작은 글자·미완성 설명·틀린 컬럼 라벨을 재현하지 않는다. OS1의 직접 참고 부재와 PM1의 주간/월간 부분 대응도 프로필 근거에 남긴다.

## 참고 서식의 실제 글꼴

참고자료의 서식을 요청받으면 같은 문서 역할의 지정 원본 SHA와 선택 프로필을 기준으로 표지·제목·본문·표 머리·값·주석 등 소유 영역별 기대 글꼴을 확정한다. 사용자 지정값과 채택한 프로필 값, 원본 관찰값을 구분한다. 특정 참고자료에서 관찰한 서체를 모든 역할의 공통 기본값으로 고정하지 않는다. 구조 원형 보존과 요청 글꼴 적용은 각각 검사한다.

실제로 텍스트를 소유한 run의 문자 정의와 글꼴 참조를 해결하여 한글·라틴·한자·일본어·기타·기호·사용자 7개 script의 fontface를 대조한다. 같은 파일의 숫자 ID나 header의 글꼴 목록만 비교하지 않는다. 기대값은 원본·프로필 SHA와 owner 위치에 연결하고, 적용 후 현재 HWPX의 같은 영역에서 실제 해결값을 다시 확인한다.

공통 렌더러뿐 아니라 이번 작성에 쓰는 임시 helper·후처리까지 확인한다. 고정된 `font=` 인수, 문자 정의·`fontRef`·기본 스타일의 직접 변경이 선택 프로필을 나중에 덮어쓰는지 탐지한다. 스크립트에 프로필 옵션을 지정했거나 글꼴 적용 함수가 성공했다는 사실만으로 완료 처리하지 않는다.

최종 native PDF에서 해당 영역의 실제 사용 글꼴과 대체 글꼴을 확인한다. PDF 전체 글꼴 목록과 본문 영역별 사용을 구분하고, subset 이름과 선언된 이름의 대응 근거를 남긴다. 예상 밖 fallback이나 대응 미확정은 해결하거나 한계로 기록하며 글꼴 일치로 통과시키지 않는다. 글꼴을 수정하면 현재 bytes로 재출력하여 줄바꿈·표 넘침·계속 쪽·목차도 다시 확인한다. 기술적 대조 방법은 `$hwpx-authoring`의 `references/quality-gates.md`를 따른다.

## 독자가 읽을 정보 구성

- AD2: 요약·요건·절차·제약·분류·근거를 구별한다. 문서 수준 합성 고지와 항목 상태를 구별하고 좁은 셀마다 긴 안내를 반복하지 않는다.
- TD3: 화면 ID·경로·그림·필드·버튼·검증·권한이 서로 대응해야 한다. 필드의 형식·필수 여부·기본값·검증 조건을 구분하고 개별 출처와 notes를 보존한다.
- TD5: 논리명·물리 ID·타입·키·NULL·기본값·암호화·제약을 비교할 수 있게 배치한다. 좁은 칸에는 정확한 짧은 표기를 쓰고 전체 의미는 연결된 상세에 보존한다. 임의 축약·ID 변경·폰트 축소로 폭 문제를 숨기지 않는다.
- PM4: 출발·도착·관계·방향·검토 상태·비고·근거를 사람이 읽는 표와 문장으로 구성한다. 직접 연결과 명시 추적 관계를 구별하고 추이적 충족이나 실제 수행을 추론하지 않는다.

`[S1]` 같은 근거 번호는 문서 안의 출처 대응표와 기계 부속에 연결한다. 본문을 간결하게 만드는 과정에서 필수 정보가 부속에만 남아 독자가 찾을 수 없게 되지 않았는지 확인한다. `false`·0·빈 문자열·null, 원문 분류와 번역된 표시, 미확인·계획·실제 결과의 의미를 유지한다.

## 문장·단어와 줄바꿈

처리 단계·입력 항목·버튼·검증 조건은 의미 단위의 문단으로 나눈다. 한국어 어절, 영문 용어, ID와 수치·단위를 칸 폭에 맞추려고 수동 줄바꿈으로 잘게 자르지 않는다. 참고자료의 단어 중간 줄바꿈도 관행으로 복제하지 않는다. 자동 어절 나눔과 정렬은 현재 문단·셀의 역할에 맞게 지정하고 실제 한컴 출력에서 확인한다.

좁은 칸에는 중복 접두어·설명을 덜고 짧은 필드명과 구체값을 배치한다. 긴 식별자는 공백·쉼표·항목 경계 등 의미가 바뀌지 않는 구분에서 나누며 값 자체를 축약·변경하지 않는다. 어절 묶음 설정만으로 긴 토큰의 넘침이 해결됐다고 판단하지 않고, 열폭·병합·폰트 크기를 임의 변경하지 않는다. 계속 쪽의 머리행과 남은 문장, 첫·마지막 값까지 현재 출력에서 대조한다.

업무 설명·요구 목록·장비 목록이 길면 문장·절차·항목의 의미 경계에서 문단을 나누고 블록 간 간격을 둔다. 사용자 검토본의 문단 분리는 내용 삭제와 구별하여 보존하되, 화면 폭에 맞춘 단어 중간 분할이나 특정 글자 수마다 Enter를 넣는 방법을 재사용하지 않는다. ID 목록을 여러 문단으로 나눌 때에도 전체 ID·순서·구분자·문장 귀속을 대조한다. 기존 글꼴·크기·줄 간격이 유지된 편집을 새 서체나 고정 크기의 요구로 해석하지 않는다.

목차의 점선 보강은 항목과 쪽번호를 읽기 쉽게 정렬하려는 편집으로 해석한다. 현재 문단 폭에 맞는 탭·리더·정렬을 사용하고 점 개수를 고정하지 않는다. 제목·하위 항목의 계층을 보존하며, 본문·그림·문단이 바뀐 뒤에는 사용자가 적어 둔 쪽수도 현재 native 출력으로 다시 확인한다.

## 그림

제공된 첨부를 의미 슬롯에 연결하고 실제 지원 media와 SHA·출처·캡션·원본 비율·크롭 여부를 확인한다. 그림 자체, 화면 ID, 본문 설명의 대응을 읽는다. 이미지가 있다는 사실은 구현·수행·승인 근거가 아니다.

실제 화면이 없으면 없다는 상태를 유지한다. 기능 시험에 사용하는 합성 시안에는 문서와 그림 안에서 실제 실행 화면이 아님을 표시한다. 필드·버튼에서 만든 시험 시안도 기본값·결과·성공 표시를 새로 만들지 않는다. 참고 그림의 재현 실험은 로컬 사본과 명시된 재현 고지에 한정하고 원문의 승인·서명을 새 사업 증거로 사용하지 않는다.

## 생성과 실제 출력의 반복

원자료→업무 표현은 값·관계·상태·출처의 의미 대응으로 검사한다. 업무 표현→서식 적용은 선언한 변경과 보호 대상을 나누어 검사한다. 서식 적용본→한컴 저장본은 현재 strict 보존 기준을 유지한다. 원시 JSON 문자열과 업무 문장의 완전 일치를 요구하지 않으며, 내용 재작성 때문에 native 보존 검사를 전역 완화하지 않는다.

같은 문안 비교로 내용량 차이를 통제한 뒤, 규칙을 설계할 때 사용하지 않은 입력을 적용한다. 짧음·장문·긴 ID·계속 표·값/타입 미확인·그림 유무에서 실제 서식 판단이 달라지는 경계를 검증한다. 한 대표 페이지의 성공을 전체19종의 성공으로 확대하지 않는다.

현재 생성 파일을 한컴에서 열어 저장·닫기·재열기·PDF 출력하고 모든 페이지를 원본 PNG로 확인한다. 수정하면 그 바이트에서 다시 출력한다. 목차 제목/항목, 모든 반복 명세표, 첫/마지막 값, 계속 쪽 식별자, 그림 글자의 인쇄 가독성을 직접 대조한다. 실제 앱 버전·현재 파일/출력/PNG 해시·검토 범위를 보존한다.

사용자가 수치 목표를 요구하면 관측 기준과 단위를 출력 검토 전에 고정한다. 이 프로젝트의95% 목표는 `resources/style-upgrade/rubric.json`에 정의한 근거 기반 판정이며 픽셀·미감 유사도의 객관적95%를 뜻하지 않는다. 낮은 문서를 평균으로 숨기거나 미검토를 통과로 계산하지 않는다. 누락·잘림·오독·의미 왜곡·허위 사실 같은 중대한 실패는 수치와 별도로 해결한다.

최종 스킬 수준은 선언된 코드·실행환경·글꼴·원본 사본·프로필·첨부와 새 입력으로 다른 작업자가 재현한 결과까지 포함한다. 스킬 폴더만으로 한컴 엔진이나 전체 저장소가 포함된다고 가정하지 않는다.
