# 사실 계약과 문체

## 근거 유형을 분리한다

| 유형 | 판단과 기록 |
|---|---|
| 양식 지침 | 선택한 로컬 양식의 원문 규정·필드/작성요령. SHA·XML 위치를 인용한다. 현재 공고의 법적 제출 요건 확인과는 구분한다. |
| 전문가 관행 | 한 사업의 문체·블록 구성·직접서식 관찰. 다른 사업의 필수 규칙이나 사실로 복사하지 않는다. |
| 사업 사실 | 이번 사업에서 제공·확인된 기업 역할·요구·장비·일정·수치·담당자·수행/승인. source_refs를 연결한다. |
| 구현 선택 | 반복 표·그림 제작·문단 배치·필드 대응 방식. 해당 양식 지침과 충돌하지 않는지 확인한다. |
| 미확인/이슈 | 원본 충돌, 자료 부족, 불명확한 역할/날짜/산식. 원문 값을 함께 보존하며 자동 정정하지 않는다. |

형식상의 필수 산출물과 개별 칸의 필수 여부를 혼동하지 않는다. v2.0 목록의 필수17/선택2는 그 로컬 목록의 관찰값이며 모든 연도에 일반화하지 않는다. 실제 대상 사업/연도/버전/역할/해시를 먼저 확인한다.

## 공통 모델

repo의 `docs/DATA_MODEL.md`, `schemas/project.schema.json`, `docs/BUSINESS_VALIDATION.md`를 필요한 필드만 읽는다. `project.requested_deliverables`는 현재 역할코드19종 중 요청 범위이며 실제 완료 문서 ID가 아니다. `requested_forms`는 34개 서식 ID를 별도로 받는다.

각 개체의 `id/name/status/source_refs`를 유지한다. `sources`는 경로·SHA·제공/검증 상태, `source_refs`는 XML 위치 또는 원시 JSON Pointer다. 상태 `provided`는 제출 승인이나 진위를 검증했다는 뜻이 아니다. 자료가 없으면 빈 문자열로 채우지 말고 `null`/빈 배열과 미확인 사유를 사용한다. 빈 배열의 의미가 미수집인지 실제 부재인지 밝힌다.

문서 추출에서는 `original_id`/`original_classification`과 `extraction_issues`로 원문을 보존한다. 표준 분류에 대응해도 원문 값을 지우지 않는다. 의심 ID를 임의 0-padding하거나 목차 번호에 맞춰 본문을 바꾸지 않는다. 해결/사유 수용은 검토 근거가 있을 때만 상태를 바꾼다.

`requirements`의 요약·상세·제약·담당자·출처를 구분한다. 기능분류와 변경구분은 다른 필드다. 실제 화면/API가 있는 보안 요구 등 분류가 모호하면 선택 양식/사업의 지침과 협의 근거를 확인하고 분류 모호성으로 기록한다. 단일 사례의 장비 중심 비기능 요건을 보편적인 모든 요구분류 규칙으로 전용하지 않는다.

## 사용할 정보 구성

- 요약은 대상과 목적을 한 문장으로 기술한다. 상세는 입력→행위/계산/연동→결과와 오류 조건을 구체적으로 쓴다.
- 업무 절차는 메뉴/화면→선택 조건→입력/버튼→저장/조회/반영 순서로 작성한다. 필수 입력·범위·중복·선행조건은 별도 체크/제약에 연결한다.
- 변경은 기존 동작과 변경안을 비교하고 요구사항·회의·변경 근거를 연결한다. “추가”, “정상”, “완료”만으로 상세를 대신하지 않는다.
- 시험은 시나리오·입력·예상·관찰 결과를 분리하고 관찰 결과에는 실제 수행 입력만 넣는다. 계획 시험은 미수행으로 둔다.
- 기대효과는 개선 의도, 성과 실측은 확인된 측정 자료다. 근거 없는 개선율·목표 달성·정상 운영을 만들지 않는다.

번호·하위 항목을 이용한 짧은 설명과 표의 반복 블록은 재사용 가능한 관행이다. 전문가의 고유 장비·기업·실명·숫자·날짜·서명·빨간색/파란색 강조를 사업 사실이나 고정 문체로 복사하지 않는다. 원문의 복사 오류, 조밀한 글자, 누락된 헤더도 모방 대상에서 제외한다.

업무 본문에는 독자에게 필요한 ID·타입·수치·조건을 명세로 배치한다. 원시 JSON 덤프, 내부 상태 enum, 긴 JSON Pointer를 문장 대신 나열하지 않는다. 짧은 근거 번호를 사용하면 문서의 출처 대응표와 `*.sources.json` 부속에서 정확한 source_id·locator·원문 상태를 찾을 수 있어야 한다. 같은 값이 문서 다른 곳에 존재한다는 이유로 해당 항목의 설명·제약·관계가 보존됐다고 판단하지 않는다. 자세한 적용과 검토는 [editorial-quality.md](editorial-quality.md)를 따른다.

## 미확인·미수행 상태와 합성 자료

자료 미제공은 수행·개최·요청·승인이 없었다는 증거가 아니다. 알려지지 않은 실제 값은 `null`과 미확인 사유를 유지한다. 계획 시험으로 명시된 경우에 `actual=null`과 `planned`/`not_run`을 사용하며, 판정 근거가 없는 시험을 스키마에 맞추려고 임의로 `not_run`으로 정하지 않는다. 회의일 누락만으로 미개최를, 설치·지원 결과 누락만으로 미수행을, 승인자료 누락만으로 미승인을 확정하지 않는다. 제공된 실제 값·검토 결과는 입력 주장과 출처를 표시하여 보존하고 진위 확인과 구분한다. 특정 역할을 담당자로 지목하거나 허구 인명·날짜·서명 이미지를 만들어 넣지 않는다.

`true`·`false`·`null`, 숫자0과 미확인, 빈 문자열과 미제공을 구분한다. 필수 여부null을 선택으로, 분류null을 비기능/이슈로, 소수 자릿수null을0으로 바꾸지 않는다. 기본값은 타입과 값을 보존한다. 보고 유형을 월간으로 일괄 바꾸지 않으며, 제목·목차·고정 안내 문구도 본문의 제공 값·수행/승인 상태와 대조한다.

synthetic dataset은 모든 의미 개체/출처에 합성 상태를 표시하고 문서 내부에도 `검증용 합성 자료(제출용 아님)`을 표시한다. 계산 fixture의 합성 KPI actual은 실제 사업 실적/시험 통과와 명확히 구분하며 출처가 합성임을 유지한다. 합성 자료의 `submission_ready`는 항상 false다.
