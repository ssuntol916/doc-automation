## 선택과 입력 계약

`project.requested_forms`에 실제 요청 서식 ID를 넣고 해당 원본 연도/버전/해시를 확인한다. `form_records`는 각 서식에 특화된 **형식이 있는 사실 필드**를 담는 계약이다. fields 항목은 `key/label/locator/value_type/value/status/source_refs`, 필요시 `author_role/review_id/notes`로 구성한다. `key`는 구현에서 정하는 안정 키이고 원본 필드명은 `label`과 실제 locator에 보존한다. 아래 입력군은 상세 구조에 대한 분석 해석이지 개별 칸의 법적 필수/선택을 선언한 목록이 아니다.

숫자·날짜·금액·백분율·목록·첨부 참조를 문자열 한 칸에 섞지 않는다. 은행 계좌번호는 앞자리0을 보존하는 text이며 은행·예금주·신고 주체·첨부와 구분한다. 고지/약정/동의/계약의 고정 문구와 사업 사실 입력을 나눈다. 원문이 요청한 표 변경 금지·사진/증빙·주체별 열 구분은 해당 서식의 지침대로 확인한다.

작성 권한이 다른 평가/감리/위원회·기관 결과, 서명/날인/합의·검수·승인은 해당 주체의 실제 근거가 필요하다. 기업이 제공한 자체 설명을 검토기관의 판정 칸에 복사하지 않는다. 자료가 없으면 null/확인 필요와 작성 주체를 남기고 정상·적정·성공·승인 또는 미수행·미승인 여부를 임의로 확정하지 않는다. 실제 계좌·비용·계약 작성은 요청 범위와 제공 사실이 있어야 하며, 이 분석/계약 자체가 작성 권한을 확대하지 않는다.

## 전용 필드 작성 예

서식8-1은 `bank_name`/`account_number`/`account_holder`(text), `bankbook_attachment`/`seal_certificate_attachment`(attachment_ref)처럼 은행·계좌·예금주·각 첨부를 분리할 수 있다. 이 key 이름은 구현 선택이다. 실제 값/locator/출처·신고 주체를 원본과 제공 사실에서 확인하며 계좌나 직인·인감 이미지 예시를 만들어 채우지 않는다. 계좌신고와 사용인감계의 고정 문구·각 기업 날인 영역은 분리한다.

서식11/12는 계획/실적·승인 목표/실측·보고기업/점검위원을 분리하는 필드와 표를 사용한다. 서식13/13-3은 감리/확인자의 판단을 기업의 시정결과와 분리한다. 서식16의 적정/보완/부적정과 성공/보완/실패를 서식16-1의 적정/부적정·성공/실패 선택지와 섞지 않는다. 선택지는 원문 구조이며 판정값은 실제 판단 자료에서만 받는다.

서식18/18-1의 제재·환수·참여제한·통지/이의절차는 기관/위원회의 실제 결정과 적용 규정 확인이 필요하다. 원본 문구의 기간·법률 인용을 오늘의 유효 규정이라고 확정하지 않는다. 서식23의 계약 조항을 고정 원문으로 보존하되 요청한 변경이 있으면 변경 범위·근거를 따로 기록한다. 임의의 계약 조건·기업/대표·서명을 생성하지 않는다.

서식10은 XML 입력표가 아닌7장 JPG다. repo catalog의 image_only_form10_review와 실제 이미지를 읽고 RCMS 등 실제 원천 보고서/거래 자료를 수집해 대조한다. OCR은 보조 추출이며 숫자/서명을 확정하는 증거가 아니다. 빈 표를 새로 만들어 원본과 동일한 양식이라고 주장하지 않는다.

## 출력/QA

해당 서식의 원문 작성요령·첨부·표/사진 제약을 본문 입력과 분리해 확인한다. 중첩표(T64/T65 등), 표 밖 약정 본문, 그림 전용 필드, 평가 주체별 열을 보존한다. 금액 단위·비용 코드·합계·재원·기간·기여율·KPI의 원문 모순을 자동 정답으로 고치지 않는다. 형식이 있는 null 입력과 실제 자료 누락을 보고한다.

생성 지원이 없는 서식은 분석/typed 입력 준비 범위로 보고하고 결과 HWPX 생성·제출 완료로 표시하지 않는다. 생성한 경우 현재 바이트의 구조·사실 검증 후 실제 한글 출력/PDF/전체 페이지를 검토하고 합성 고지·미확인·서명 영역·페이지 넘침을 확인한다. 서식의 존재가 실제 계약·검수·기관 판정의 증거는 아니다.
