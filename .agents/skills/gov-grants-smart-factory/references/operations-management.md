# 운영·관리 6종과 KPI 보조 안내

**양식**은 로컬 원문 지침, **관행**은 전문가 한 사업 관찰, **작성/QA**는 생성 권고다. 양식 필드·반복·원문 위치·SHA는 repo `resources/stage1/test-management-requirements.json`에서 code로 찾는다. 개별 참고자료의 관측·정합성 판단·시각검토 근거는 비공개 로컬 입력에 보존한다. 공개 스킬에는 그 원사업 값이나 판정을 포함하지 않는다. 관계는 `resources/stage2/mapping.json`을 따른다. 자원은 이 스킬의 `scripts/run.py path <repo상대경로>`로 찾는다.

문단 범위/다중 표 표기는 읽기 안내다. 실제 source_refs에는 원본의 단일 문단/표/논리 셀 위치를 각각 넣는다. 이 보고서 일부의 물리 행/셀 표기와 공통 프로필의0 기반 cellAddr 표기는 구분한다.

## SF-OS1 운영지원계획서

**양식:** 전환 이후~사업 종료의 HW/SW/NW/시스템/초기데이터 지원대상·인력·헬프데스크 즉시 대응·로그인/사용시간/기능활용 분석·추가교육·활성화 방안을 계획한다. 로컬 목록상 선택 문서이나 실제 사업 적용 여부를 확인한다. 원문 `Contents/section0.xml#P71,P73~76,P78~81`.

**관행:** 같은 역할의 전문가 참고 문서는 없다. 다른 결과보고를 계획서의 성공 사례로 간주하지 않는다.

**입력/작성:** `project.support_activities`와 실제 지원대상·지원 기간·담당 역할/인력·연락·분석 지표/주기·교육/활성화 발동 조건. `deployment_items`, `operation_periods`와 연결하되 계획과 수행 결과를 구분한다.

**피할 오류/QA:** 없는 지원 수행·담당 실명·교육·성과를 창작하지 않는다. 표지 사업명·지원 범위/기간·대응 책임/시간·발동조건의 출처를 확인한다. 선택 산출물이라는 이유로 실제 변경/요청 범위에서 빠져도 된다고 일반화하지 않는다.

## SF-OS2 운영현황보고서

**양식:** 구축/설치·환경설정과 해당시 클라우드, 주간 등록/거래 활용, 일별 로그인/사용자별 접속시간과 증적, 장애/조치·공급기업 지원을 구분한다. 원문 `Contents/section0.xml#P57,P59~61,P64~67`. 목차/본문의 구축(4) 누락 등 원본 차이를 확인한다.

**관행:** 설치목록→시스템/모듈 규모→화면별 주간 집계→일별 사용자 건수/시간→장애→추가 지원. 사양은 키/값, 조치는 대상·문제·수정·상태로 간결히 기록한다.

**입력/작성:** `deployment_items`, `operation_periods.raw_records/reported_totals/aggregation_method/aggregation_rules`, 장애 `defects`와 지원 내역·실제 원시 로그. 사용자/일별·등록/조회/거래량·사용시간을 서로 다른 지표로 정의한다. 누락 값과 실제0을 구분하고 분모·기간·중복 처리도 명시한다.

**피할 오류/QA:** 참고의 주/열 합계·사용시간 총계·연도·중복 날짜·표지월/설치확인일 차이를 복사하지 않는다. 원시행→행/열/전체 합계·평균을 검산한다. 사용자별 비정상 장시간은 실제 집계 정의를 확인하며 오타로 단정하지 않는다. 화면 조회수를 등록량으로 전용하지 않고 로그 화면이 없으면 증빙 충분성은 미확인이다.

## SF-PM1 월간보고서

**양식:** 보고월/기간·과제명·금월/누적 계획/실적 진도·관리/개발 영역의 단계/투입인력/작업·차월계획·위험/이슈·작성일/공급기업PM 날인을 다룬다. 원문 `Contents/section0.xml#P29,P31~33,T2,T3,P115~116`.

**관행:** 참고는 **SF-PM2 주간보고**로 주기가 달라 부분 대응이다. 금주실적/차주계획을 사업관리/개발관리→단계→구체업무로 나누고 완료/검토/협의와 예정 표현을 구분한다. 이를 월간 실적이라고 이름만 바꾸지 않는다.

**입력/작성:** `progress_reports`의 실제 report_kind/기간, 금월/누적 계획/실적·가중치/산출기준, work_items/risks, 실제 작성/검토/날인. 주간 자료를 월간으로 집계할 때 기간·누락 주·중복 작업·진도 산식을 확인한다. 주간 예시만 있으면 부분 대응/월간 입력 필요를 남긴다.

**피할 오류/QA:** 참고의 연도024·누적 증분과 주간 진도 차이·장비 변경 사유 오기는 모방하지 않는다. 현재/누적과 계획/실적을 구분하고 숫자를 원장에서 계산한다. 계획/미수행을 완료 실적으로 쓰거나 서명 이미지를 재사용하지 않는다.

## SF-PM2 회의록

**양식:** 일시/요일·장소·주최자·안건·회의내용·합의·특이사항·소속별 참석자를 기록한다. 실제 칸은 `Contents/section0.xml#T2/R0C0~R7C0`의 논리 셀과 원문 지침에서 확인한다. 전문가 파일은 SF-PM4로 역할 대응한다.

**관행:** 배경/이슈→당사자 의견→처리방안/제안→결과를 분리하고 논의 뒤 관련 화면/표를 둔다. 화살표·괄호 조건·번호 계층은 관행이며 필수 기호가 아니다.

**입력/작성:** `meetings`의 실제 개최일/시각·요일·주최·참석·논의·결정, 자료/변경/요구 연결과 실제 서명 근거. 회의 계획은 개최·참석·합의와 구분하며 가상 참여 역할을 실제 참석자로 채우지 않는다.

**피할 오류/QA:** 날짜/요일 오기·본문 완료수와 결과 남은수 불일치·빈 합의·2019 잔여 머리말을 확인한다. 회의 내용과 결정/후속 조치·책임·기한이 맞는지 읽는다. 장문 `pageBreak=NONE` 표의 실제 분할/상단 위치는 출력에서 검토한다.

## SF-PM3 변경관리내역서

**양식:** 변경 대장과 요청서, 사유·전후·영향/파급, 요청/회신 공문·날짜·주체, 양 기업 서명 회의록·관련 증빙·기관 승인 공문/확인 화면을 관리한다. 로컬 목록상 선택이며 실제 변경/사업 처리기준은 별도 확인한다. 원문 `Contents/section0.xml#P111,P113,P117,P122~126`. 전문가 파일은 SF-PM5다.

**관행:** 전체 대장→변경별 요청서+공문/관리화면 묶음을 반복하고 전후 사양/기간을 같은 항목으로 비교한다.

**입력/작성:** `changes`의 categories·요청/회신 번호/날짜/내용·requester·reason/before/after/impact·approval_status/approval_evidence_ids·meeting_ids/affected_refs. 실제 변경 검토안과 승인된 변경을 구분한다. 승인 없이 요청/승인 번호를 만들어 채우지 않는다.

**피할 오류/QA:** 참고의 도입/공급기업 역할 역전·공문 캡션 뒤바뀜·일자 차이·빈 공문번호·일괄 영향없음을 모방하지 않는다. 대장/요청서/증빙의 동일 사건 키·기업 역할·변경 대상/범위·승인 상태와 각 날짜를 대조한다. 근거 없이 “영향 없음/승인 완료”를 쓰지 않는다.

## SF-PM4 요구사항추적표

**양식:** AD2의 ID/명/설명, 기능별 화면·프로그램·단위/통합/사용자시험 ID와 추가/변경/삭제 근거, 비기능 결과물·이행현황을 연결한다. 원문 `Contents/section0.xml#P136~144`. 전문가 파일은 SF-PM7이다.

**관행:** 기능 행은 요구→화면→프로그램→단위→통합→사용자시험으로, 비기능 행은 결과문서/설치일로 설명한다. 원문의 행 수나 일련번호를 고정하지 않는다.

**입력/작성:** `trace_links`의 실제 source/target 도메인·ID·관계·근거·content_review_status, 요구 완료 상태와 실제 결과물/추진 근거. 복수 ID는 배열/여러 관계로 관리하고 표시 정책을 일관되게 쓴다. 미해당과 미확인을 구분한다.

**피할 오류/QA:** 참조 대상의 ID 존재·원문 ID명칭 일치는 필요 검사지만 의미 충족/수행의 증거가 아니다. 모듈명이 다르더라도 실제 테스트 절차가 맞을 수 있으므로 케이스를 읽는다. 참고의 변경 근거 비고 누락·문서별 하드웨어 규격/설치일 차이·이어지는 표 머리행 누락을 긍정 패턴으로 삼지 않는다.

## KPI 성과측정 — 19종 밖의 보조 참조

전문가 SF-PM6 성과측정 문서는 현재 19종 목록에 독립 대응 양식이 없다. 2025년 서식 묶음의 KPI 관련 지침은 해당 서식의 보조 근거로만 쓰며 임의의20번째 코드나 모든 사업의 공통 KPI 요건을 만들지 않는다.

**관행:** 요약 수치→달성/개선 산식→기준/실적 원천값→지표 정의/기간/기준→결과 화면으로 근거를 좁힌다. 빨간 박스/화살표는 가독성 선택이다.

**입력/작성/QA:** `kpis`의 단위·개선방향·산식종류/문장·분자/분모·기준/목표/실적·기간·각 근거를 구분한다. 참고의 원천 숫자는 계산이 맞아도 분자/분모 설명 문장이 반대인 사례가 있으므로 식과 문장을 함께 검증한다. 실제 계측 자료 없이 성과/성공을 생성하지 않는다. 합성 계산 fixture는 실적이 아닌 검증용 합성값으로 문서 안에도 구분한다.
