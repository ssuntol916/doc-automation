# 도메인 작성 품질 검토

패키지/네이티브 검토는 `$hwpx-authoring`의 quality-gates 참조와 repo `docs/OUTPUT_QUALITY.md`를 사용한다. 이 문서는 그 앞의 내용 검토를 담당한다.

## 요청 범위와 사실

사업명·연도·과제명·기업 역할·양식 버전·기간이 실제 원자료에 일치하는지 확인한다. 파일 표지의 연도와 사업연도·수행연도가 다를 수 있다. 사용한 원본 해시와 역할 매핑을 남기고 현재 규정 확인 여부를 구분한다. 참조 기업의 신상·서명·장비·숫자·날짜가 새 사업에 남지 않았는지 검사한다.

현재 source 파일·해시·인용 위치가 존재하는지는 `validate-project`로 확인하되 사실 진위로 해석하지 않는다. 원문 이슈가 JSON schema 정상이라는 이유로 사라지지 않게 한다. 미확인·미수행 상태 및 합성 고지가 출력 문서에서도 보이는지 확인한다.

## 문서 간 일치

- 요구 ID·명칭·변경 전후·요건/제약과 화면 체크·프로그램 로직·테이블·시험을 대조한다.
- AD2는 기능/비기능/유형 미확인의 상세 카드·목차 그룹과 각 그룹 내부 순서가 제공 `kind`와 맞는지 확인한다. null을 비기능으로 옮기거나 ID를 바꾸지 않는다. TD3의 3-3-3 ID 지침 차이는 선택 원본별 경고로 보존하고 사업 공통 의무로 확장하지 않는다.
- ID는 문서/시험 단계의 범위로 구분한다. 존재 검사를 내용 충족 검사로 대신하지 않는다. 모듈명 차이만으로 오류를 확정하지 말고 실제 절차/케이스를 읽는다.
- 날짜의 연도·월일·요일·기간과 변경 요청/회신·회의/시험/설치 순서를 확인한다. 근거 없이 날짜를 맞춰 고치지 않는다.
- 운영 원시행→행/열/전체 합계·기간·평균의 분모·사용자 중복을 검산한다. 사용자-일수 합계를 고유사용자 수로 표시하지 않는다.
- KPI 단위·분자/분모·기준/목표/실적·개선방향·실측기간을 확인하고 숫자와 산식 문장을 함께 대조한다. 목표 미달을 오류나 성공으로 재작성하지 않는다.
- DB 논리명/물리ID·중복·타입/자리수·PK/FK·nullable·기본값·암호화 정책을 별도로 확인한다. 문서상의 이름이 실제 물리DB와 같은지는 실제 export 근거가 필요하다.
- `false`, `0`, 빈 문자열, 빈 배열/객체와 `null`을 구분한다. 기본값·필수 여부·분류·암호화의 미확인을 선택/비기능/미적용으로 바꾸지 않는다. 표가 짧은 참조키를 쓰면 전폭 상세에 전체 값·테이블 설명/제약·출처가 남아 있는지 확인한다.
- 추적표는 기능/비기능/미확인 분류 모두의 명시 연결을 확인한다. 화면·프로그램·DB·시험단계별 직접/역방향 관계, relation·상태·notes·source를 보존하고 그래프를 가로지르는 추이 관계를 사실로 추가하지 않는다. 도메인 ID가 존재한다는 사실은 내용 검토나 실제 시험 충족을 뜻하지 않는다.
- 승인·서명·시험결과·설치 확인·물리DB Excel·외부 매뉴얼 등 외부 증거를 실제 제공 파일/이벤트와 연결한다. 그림/OCR만으로 수행 진위를 확정하지 않는다.
- 미확인 필수 여부·분류·수치가 선택·비기능·이슈·0 등으로 바뀌지 않았는지 확인한다. 제목·목차·고정 고지의 미수행/미승인 단정이 본문의 실제 입력·검토 결과와 충돌하지 않는지도 대조한다.

## 출력 단계

생성 manifest에서 실제 요청 역할·지원 결과와 입력/양식/HWPX의 해시를 읽는다. 현재 HWPX를 실제 한글에서 열고 PDF·전체 페이지 PNG를 남겨 `verify-output`으로 기록의 바이트/페이지 대응을 검사한다. 실제 한글 버전·호환성 안내·검토자/시간·contact/확대 페이지 범위를 보고한다. 옛 기준 PDF를 새 생성물의 품질 증거로 쓰지 않는다.

표 잘림·넘침·글자 충돌·읽기 크기·연속 표 머리행·증적 판독·머리말 잔여 사업명·목차/쪽번호를 확인한다. 원본 결함·환경 호환성·생성 오류·원인 미확인을 분리한다. 실패/대기 페이지를 통과로 채우지 않는다. 네이티브 출력 pass도 사업 사실·담당자 승인·실제 제출 가능의 승인이 아니다.

참고 대비 편집 수준을 판단할 때는 [editorial-quality.md](editorial-quality.md)의 같은 문안 비교와 새 입력 검토를 함께 수행한다. 폰트·줄간격·열폭의 실제 적용과 독자의 읽기 흐름은 서로 다른 근거다. 모든 표가 XML에 존재해도 floating 표가 실제 출력에서 겹치거나 빠질 수 있으며, 목차의 내용이 존재해도 제목과 다른 쪽으로 갈라질 수 있다. 페이지별로 해당 항목·머리행·첫/마지막 값을 확인하고 실패를 수정·재출력한다.
