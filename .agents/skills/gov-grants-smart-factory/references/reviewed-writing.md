# 검토본에 맞춘 보고서 문체와 요약

사용자 검토본의 직접 수정은 해당 보고서의 문체·정보량·표현 기준이다. 변경되지 않은 서식을 임의로 새로운 표준으로 정하지 않는다. 이 참조는 양식 구조를 바꿀 권한을 주지 않는다.

## 주요 내용과 목표

검토본이 주요 내용을 여러 항목으로 나눴다면 각 제목을 유지하고 항목별 설명과 확인 가능한 목표를 대응한다. 서로 다른 항목을 하나의 포괄 문장으로 다시 합치지 않는다. 계획의 목표와 중간 수행 상태를 구분하고, 정량 목표가 없는 항목에 구현률·정확도·달성률을 만들지 않는다.

같은 셀 안에서 항목 제목과 설명을 구분한 검토는 그 문단·run 경계를 유지한다. 제목은 검토본의 강조, 설명·목표는 보통 본문 역할로 두고 항목 사이를 읽을 수 있게 구분한다. 셀 전체를 같은 굵기의 긴 문단으로 합치거나 항목 구분을 위해 셀을 추가하지 않는다.

목표 확인 요청은 사업계획의 목표 표·측정방법·관련 발표 내용을 대조한다. 서로 다른 지표의 목표를 특정 기능의 성능값으로 전용하지 않는다. 원문에 상충이 있으면 계획값과 미해결 근거를 구분해 원장에 남긴다. 계획된 연계 시스템의 이름은 현재 연결 완료를 뜻하지 않는다.

## 요약과 구축 전·후 설명

검토본이 요약에서 명사형의 짧은 문장으로 바꿨다면 해당 요약·주요내용에도 그 문체를 유지한다. `본 과제는`, `제공 자료에 따르면`, `확정하지 않았다` 같은 작성 과정 설명을 핵심 업무 설명보다 앞세우지 않는다. 이 선택으로 계획을 완료 실적이나 사실 확정으로 바꾸지 않는다.

구축 전 설명은 해당 공정·기존 시스템·주요 문제를, 구축 후 설명은 계획된 데이터·업무 연결·사용자 조치·예상 활용을 간결히 대응한다. 사용자가 요청한 그림 아래 설명을 자료 검증 과정이나 원자료 오류 목록으로 대체하지 않는다. 핵심 업무 사실과 계획/실제 구분은 본문에 남기고 상세 출처·검산·상충 분석은 연결 원장으로 관리한다.

`3~5줄` 등 분량 요청은 해당 양식의 글꼴·본문 폭으로 실제 출력된 줄 수를 확인한다. 문장 개수나 XML 문단 수만으로 충족을 판정하지 않는다. 불필요한 설명을 덜어 맞추며 글꼴·열폭 축소나 표 재설계로 해결하지 않는다. 짧은 요약은 한 쪽에서 이어 읽을 수 있게 하고, 새로 작성한 요약 문단의 쪽 경계에서 분리되면 그 문단의 줄 묶음 등 최소한의 배치 조정만 사용하여 다시 출력한다.

## 공정 설명과 그림의 역할

검토본이 공정별 설명을 `데이터 소스 / 데이터 수집 / AI 적용`으로 나눴다면 기존 셀 안에서 그 구분을 채운다. 소스는 생산 설비·센서·업무 시스템·문서 등 실제 입력, 수집은 인터페이스·주기·저장/연계 경로, AI 적용은 입력을 이용한 판단·예측·제안과 사용자의 조치·출력을 설명한다. 확인된 내용만 배치하고 같은 포괄 문장을 세 라벨에 반복하지 않는다. 수집 자동화와 AI 판단, 작업자 승인과 자동 제어는 서로 구별한다. 이 구분을 새 열·셀을 추가할 이유로 삼지 않는다.

AS-IS의 문제를 공정도에 연결할 때는 자료에 있는 공정명·번호와 데이터가 끊기는 위치, 그 원인, 업무·품질에 미치는 영향을 대응한다. TO-BE는 그 문제를 어떤 수집·연계·판단·조치가 개선하는지 이어 설명한다. 일반적인 제품 기능 나열이나 반복되는 확인 문구로 이 대응을 대신하지 않는다. 상세 공정 설명이 추가돼도 별도로 검토한 짧은 요약까지 불필요하게 늘리지 않는다.

업무 흐름도는 공정·주체·입출력·인계/조치 순서를, 시스템 아키텍처는 데이터 원천·수집/저장·분석/검색·AI 역할·사용자/외부 시스템의 연결을 설명한다. 사용자가 두 관점의 그림을 추가했으면 하나를 다른 하나의 중복으로 지우지 않는다. 그림 안의 용어와 연결을 근거로 본문을 보강하되 자료에 없는 프로토콜·주기·제품·제어 권한을 만들지 않는다. 그림의 존재는 구현·연동 완료의 증거가 아니다.

장비 설치 위치 설명은 확인된 계획 위치·대상 공정·신규/기존 구분·배치 목적·데이터/운영 연결을 그림에 대응한다. 계획으로 알 수 있는 설명을 `현장 확인 필요` 한 문장으로 대체하지 않는다. 실제 설치·검수 여부와 미확인 세부사항은 별도로 표시한다.

## 성과지표의 기준 근거와 개선 방안

검토본이 기준값 산출근거나 개선안을 요청하면 사업계획서의 해당 표·측정 설명·원시 근거를 찾아 지정한 위치에 설명한다. 산출근거에는 자료에 있는 측정 대상·기간·분자/분모·단위·집계 방식·계산 결과를, 개선안에는 어떤 문제와 조치가 해당 지표를 개선하려는지 대응한다. 기존값·목표표를 다시 복사하거나 새 목표율을 임의 계산하는 것으로 대체하지 않는다.

검토본에 추가된 과거 실측 주장과 승인 계획의 기준값이 다르면 두 값의 시점·대상·산식을 먼저 구별한다. 검토본이 더 최신이라는 이유로 KPI 기준을 자동 교체하지 않는다. 비교 가능한 값인지와 변경 승인 여부를 원장에 남기며, 문서가 주장하는 측정과 확인된 측정 증빙도 구별한다.

## 본문과 검토 자료

서식 정리 요청에서는 항목 번호·소제목·순서·내용의 절 귀속과 표 구조를 유지한 채 글꼴·크기·색·기울임·자간·장평·줄 간격·정렬·들여쓰기를 역할별로 정리한다. 본문과 표 값은 읽을 수 있는 보통체, 제목과 표 머리는 위계가 있는 강조로 구별한다. 같은 역할의 구축 전·후 요약은 같은 서식으로 작성한다. 원본의 예시용 파랑·회색 기울임이나 빈 문단의 제목용·극소 서식은 업무 본문의 편집 기준으로 삼지 않는다. 수치 선택은 현재 양식 폭과 검토본의 실제 서식에 근거하며 특정 글꼴·크기를 모든 사업의 규정으로 만들지 않는다.

사용자가 제거한 초안 제작 안내나 원시 `[S… T…]` 코드를 본문에 되살리지 않는다. 출처 연결 자체는 비공개 원장에 보존한다. 근거표가 양식 또는 사용자 요청으로 필요한 경우에는 그 지정 위치를 사용한다. 선택 입력의 공란과 실제 미확인은 구분하며, 사용자가 공란으로 정한 칸을 일괄 미확인 안내로 채우지 않는다.

계약·약정의 고정 문구, 필요한 작성 주체 구분, 합성 예제 고지, 실제 측정·승인·서명의 경계는 계속 지킨다. 단정적 표현을 피하려고 모든 칸에 긴 유보 문구를 반복하는 대신, 항목에 맞는 상태와 근거를 명확하게 관리한다.

사용자가 반복 상태 문구나 미확인 안내 그림을 지운 경우 그 표시를 되살리지 않고, 남긴 공통 상태 설명과 연결 원장에서 미확인을 관리한다. 검토본의 숫자 공란을 0이나 진척률로 채우거나 지운 안내 그림을 실제 측정 그래프로 대체하지 않는다. 양식에서 요구하는 증적과 선택적 안내 그림을 구별하고, 삭제 후 남은 그림 참조 문구도 함께 점검한다.
