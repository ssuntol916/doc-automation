# 시험·전환·매뉴얼 5종 작성 안내

**양식**은 로컬 원문 요약, **관행**은 전문가 한 사업의 관찰, **작성/QA**는 이번 사실에 적용할 권고다. role 코드와 원문 ID 접두사를 구분한다. CD1 문서의 CD2, TI4 문서의 TI5 안내 잔여값을 임의 정답으로 전용하지 않는다.

필드·반복단위·SHA·원문 지침 위치는 repo `resources/stage1/test-management-requirements.json`에서 `code`로 조회한다. 원문 본문과 구조는 `resources/stage1/test-management.md`, 개별 참고자료의 상세 비교·판정·오류는 비공개 로컬 관측 자료다. 아래 `PAT-*`는 일반 작성 흐름의 참조명이며 실제 사업값이나 수행 판정을 제공하지 않는다. 다중 문단/범위 표기는 읽기 안내이며 실제 source_refs에는 원본의 단일 문단/표/셀 위치를 각각 넣는다. 자원은 이 스킬의 `scripts/run.py path <repo상대경로>`로 찾는다.

동일 문안 비교에서 과거 시험 화면·설치 사진을 재현해야 하면 repo `docs/REFERENCE_QUOTATIONS.md`의 `test_cases[*].reference_result_quotations`(TI1/TI4) 또는 `deployment_items[*].reference_installation_quotations`(TI2)를 사용한다. 초기 지원은 등록한6개 원문 소유 인스턴스다. 원문 provenance와 literal을 검증하고 각 그림에 ‘참고 원문 재현·새 사업 수행/설치 증거 아님’을 표시한다. 원문 '적합'·장비사진은 새 사업 결과나 실제 설치 증거가 아니므로 evidence/flow·actual/result로 전용하지 않는다. 작은 라벨은 전체 원본을 유지한 `detail_regions`로 추가 확대할 수 있으나 명시한 Mac PNG 프로필과 원본 픽셀 좌표·Q/D키·역사적 소유 고지를 사용해야 한다. 새 현재 출력의 실제 원페이지에서 판독하기 전에는 가독성·G01/G02/G03 합격을 선언하지 않는다. 확대 보기는 원래 평가 단위를 늘리거나 실제 수행·필수 artifact 의무를 면제하지 않는다.

## SF-CD1 단위테스트결과서

**양식:** 기능별 시험 ID/명칭·시나리오·테스트 데이터·예상/실제 결과/증적과 결함번호·연결 시험·발생일·원인·조치/증적·완료일을 구분한다. 원문 지침 `Contents/section1.xml#P109,P111~117,P119~120`.

**관행:** 조회조건/선택→필드 입력→버튼 동작을 시나리오에, 필드명:구체값을 데이터에, 식별키의 저장/조회 결과를 예상에 쓴다(`PAT-TEST-01`). 결함은 증상→시험ID→발생→원인/수정층→조치→완료로 설명한다(`PAT-TEST-03`).

**입력/작성:** `test_cases.stage=unit`, requirement/program 연결·입력·예상·실제 실행일/실행자/환경·증거, `defects`. 조건→입력→동작을 시험별로 구체화하고 예상 저장·조회·거절 결과를 작성한다. 실제 결과·실행일·수행자·증거가 없으면 해당 칸만 `확인 필요`로 두고 문서 전체를 제작 안내로 대체하지 않는다. `actual=null`과 계획 상태를 보존하되 `not_run`은 미수행이 확인된 경우에만 쓴다. 발생하지 않은 결함을 만들지 않으며 결함 원장 미제공도 결함 없음으로 판정하지 않는다.

**피할 오류/QA:** 동일 결함번호는 시험 단계/문서 범위로 식별한다. 예상과 관찰값의 구체값·판정 일치, 시험/발생/조치 순서, 미해결/재시험을 대조한다. 같은 화면을 재사용했다는 사실만으로 허위 수행을 단정하지도, 통과를 확정하지도 않는다. 원문 분류·기간·누락은 비교 보고서의 이슈로 보존한다.

## SF-TI1 통합테스트결과서

**양식:** 공정명·시험 ID/명칭·업무흐름도·절차/조건별 케이스·입력·예상·실제/증적, 결함/조치를 작성한다. 개발자 관점의 공정 스마트화 확인이라는 범위를 따른다. 원문 지침 `Contents/section1.xml#P71,P73~80,P82~83`의 외부 인용 문서 정체/버전도 확인한다.

**관행:** 업무영역 1개=상위 시험ID+흐름도+여러 케이스 행(`PAT-TEST-02`). 참고 TI1은 7개 상위 ID와 53개 실제 케이스이며 그 수를 다른 사업의 요건으로 고정하지 않는다.

**입력/작성:** `test_cases.stage=integration`, process/group/case_number와 요구/프로그램/화면 연결, 시나리오·데이터·예상·실행 결과·결함·증적. 연결이 필요한 선행/후행 기능과 데이터 키를 명확히 한다. 상위ID와 케이스 수를 혼동하지 않는다.

**피할 오류/QA:** 요구 ID가 직접 없는 시험문서를 추적표의 ID 존재만으로 요구 충족으로 판단하지 않는다. 실제 케이스 절차를 읽어 연계를 확인한다. 모듈명과 요구명 차이만으로 부적합을 확정하지 않는다. 케이스별 실행 상태/증거·공정 흐름·결함 연계와 연속 페이지 머리행을 확인한다.

## SF-TI2 시스템전환결과서

**양식:** 계획/착수의 HW/SW/NW와 실제 설치 규격·수량·상태·검증, 업무별 프로그램/물리DB·환경전환, 해당시 클라우드, 초기데이터 건수·정합성/충분성·도입기업 확인을 기록한다. 필요한 실제 확인/서명은 별도 근거다. 원문 지침 `Contents/section0.xml#P68,P70,P72~76,P78~81`.

**관행:** 대상 요약→모델/수량/Serial→설치 사진→라벨/시스템 정보→거래자료(`PAT-TRANS-01`), 프로그램/DB 집계→환경설정→초기데이터 전후 건수/확인→유형별 화면(`PAT-TRANS-02`).

**입력/작성:** `deployment_items`의 계획·실제 규격/수량·설치일/상태·검증방안/결과·license·migration_counts, 실제 증거/검토. 장비/전환 대상 키로 AD2·TD2·전환 결과를 연결한다. 초기데이터 건수는 대상·원본건수·전환건수·비교/오류 기준을 나눈다.

**피할 오류/QA:** 사진 수를 납품/설치 수량이나 기능검증으로 대체하지 않는다. 논리기능 수·개발 프로그램 본수·물리 테이블 수를 구분한다. “100%/정상/확인”은 실제 근거가 있을 때만 기록한다. 문서별 모델/규격·일정 차이는 변경 근거를 확인하고 실제 설치/서명을 보완하지 않는다.

## SF-TI3 매뉴얼

**양식:** 사용자와 관리자(운영자)를 구분한다. 개요·구성/메뉴·공통 사용·화면별 절차/기능/이벤트/제약, 상용/응용SW 설치·환경·시작/종료·업그레이드, 권한/보안·장애/백업복구·연락망·해당시 클라우드 절차를 다룬다. 원문 지침 `Contents/section0.xml#P69,P71~73,P79,P81~82,P84~90`.

**관행:** 개요→구성도/설명→역할 메뉴 매트릭스→공통UI→사용자/관리자 절차(`PAT-MANUAL-01`). 번호가 붙은 그림/화살표와 같은 번호의 동작, 장애 흐름과 담당 역할, 백업/복구의 선택→진행→완료 화면을 연결한다(`PAT-MANUAL-02`).

**입력/작성:** `project.manual_sections`, 실제 버전·화면/절차·역할·설치/운영 환경·장애/백업/복구 정책·연락처·첨부. 실제 매뉴얼/온라인 URL의 제공·접근·버전/보관 상태를 확인한다. 문서에 “별도 제공”이 있다는 것만으로 전달 완료를 주장하지 않는다.

**피할 오류/QA:** 참고의 연락처·계정·포트·특정 백업 일정·보안 마스킹을 일반 기준이나 새 사업 사실로 복사하지 않는다. 두 독자군의 해당 항목이 실제 포함되는지, 화면 번호와 행동 설명이 일치하는지, 그림/글자의 크기가 읽히는지 검토한다. 설계 초안과 실행 화면은 구분한다.

## SF-TI4 사용자테스트결과서

**양식:** 도입기업 담당자가 운영환경에서 공정 스마트화 결과를 확인하는 시험이다. 시험ID·명칭·흐름도·케이스/입력/예상/실제·증적·결함 조치와 업무담당자/확인자를 관리한다. 원문 지침 `Contents/section1.xml#P76,P78~85,P87~88`; 실제 표에 추가된 담당자 칸도 확인한다.

**관행:** TI1과 같은 상위 업무/여러 케이스 구성이 관찰된다(`PAT-TEST-02`). 서로 다른 단계의 케이스 명칭 일치가 독립 사용자 수행·승인을 증명하지는 않는다.

**입력/작성:** `test_cases.stage=acceptance`, 실제 도입기업 시험 담당자·운영환경·실행일·판정·관찰/증거·결함·검토. 개발자 시험 결과를 사용자 시험 결과로 단순 복사하지 않는다. 계획 상태와 실제 수행 여부를 구분하고 결과 미확정은 실제값 null로 유지한다. 담당자·확인자·서명을 가정하지 않는다.

**피할 오류/QA:** TI4 역할과 TI5 잔여 ID지침 충돌, 독립 공정명 칸의 부재, 표/지침 필드 차이를 기록한다. 요구 추적·실제 케이스·담당 역할·증거·조치/재시험과 명시적 사용자 확인을 별개로 검토한다. 장문의 표/그림이 분할될 때 케이스 문맥과 머리행이 유지되는지 확인한다.
