# 중간보고서 분석 질문

선택한 사업·연도·양식 SHA와 작성 주체를 확인한 뒤 실제 제목·표·필드를 기준으로 적용한다. 아래 범주는 분석 질문이며 모든 정부지원사업에 공통인 필수 서식 목록이 아니다.

| 범주 | 기준과 대조 질문 | 필요한 추가 근거 |
|---|---|---|
| 식별·범위 | 과제번호·기업 역할·사업장·기간·승인된 버전이 무엇인가 | 협약/변경 승인·보고 기준일 |
| 구축 개요 | 공정 문제, AS-IS/TO-BE, 목표 수준·구축 경계가 무엇인가 | 현재 공정/자산 자료, 변경 근거 |
| AI 과업 | 대상 공정·입출력·모델/데이터·평가계획과 구현 경로가 대응하는가 | 대상 데이터·라벨·버전·시험 원시값 |
| SW/HW·연계 | 계획 기능/화면/설비와 정적 코드·도입/설치·연동 근거가 대응하는가 | 납품·설치·연계 시험·운영 기록 |
| 일정·산출물 | 단계별 약속·현재 산출물·기준일의 수행 상태는 무엇인가 | 일정 변경·제출/검토 이력, 진도 산정근거 |
| 비용 | 사업계획·원가/견적·승인예산·실집행이 단위·VAT·기간별로 맞는가 | RCMS·세금계산서·이체·검수·급여 증빙 |
| KPI | 기준·목표·측정법과 중간 실측이 같은 조건인가 | 기간·표본·원시 로그·측정 확인 |
| 교육·안전·보안 | 계획 내용과 실제 수행 근거가 구분되는가 | 교육/수료·점검·설정/복구 기록 |
| 이슈·향후 계획 | 범위·일정·비용·품질 위험과 대응이 어떤 근거에 연결되는가 | 담당 역할·기한·관련 변경/협의 자료 |

보고자 작성 범위와 위원·감리·기관의 판정/승인란을 구별한다. 보고자의 자료를 기관 판정으로 복사하지 않는다. 양식의 필수 사진·서명·측정자료가 없으면 그 사실을 표시하며 계획도·예시 그래프·합성 서명으로 채우지 않는다.

각 범주 결과에는 사용 가능한 주장 ID, 비교한 source ID, 원문 불일치, 미확인 사실, 추가 자료와 작성 준비도(supported/partial/missing/conflict)를 적는다. 작성 준비도가 partial이라도 확인된 부분의 분석은 계속할 수 있다. 보고 기준일이나 승인 버전을 모르면 그 영향을 받는 수치·진척 판정을 보류한다.

## 공정·데이터·AI의 연결 근거

공정별 스마트화 설명이나 검토본의 세부 작성 틀이 있으면 다음 대응을 기존 분석 원장에 정리한다. 이 대응은 분석 관점이며 보고서에 열·표를 추가하라는 지시가 아니다.

| 대응 | 자료에서 찾을 내용 |
|---|---|
| 현행 문제 | 공정명/번호, 단절 위치·원인, 수작업·오류·품질/업무 영향과 그 근거 |
| 데이터 소스 | 해당 공정의 설비·센서·업무 시스템·문서와 실제 제공 데이터 |
| 데이터 수집 | 알려진 인터페이스·주기·수집 주체·저장/통합 경로, 계획과 실제 상태 |
| AI 적용 | 입력→판단/예측/제안→출력·사용자 조치, 자동 제어 여부와 권한 |
| 개선 연결 | 현행 문제를 줄이려는 조치, 관련 KPI·기대효과, 측정/실행 근거의 유무 |

공정 흐름도와 시스템 아키텍처는 설명 목적을 구분해 읽는다. 전자는 공정·업무 순서와 인계를, 후자는 원천→수집/저장→분석/AI→사용자/연계 시스템의 연결을 대조한다. 연결선이나 제품명만으로 연동 완료를 확정하지 않는다. 보고서의 위치도 설명에 필요한 계획 위치·배치 목적·운영 연결도 수집하되 현장 설치 증명과 구분한다.

검토본에 새로 들어온 그림의 데이터 개수·수집 주기·제어/승인 권한도 기존 본문·표·다른 그림과 대조한다. 값이 다르면 적용 공정·데이터 묶음·계획 연도·구현 단계를 먼저 확인하고 같은 범위인지 미정인 차이와 확정 상충을 구별한다. 그림의 최신성이나 OCR 추출만으로 기존값을 교체하지 않는다.

KPI 기준값의 산출근거와 개선안 요청은 숫자 추출만으로 완료하지 않는다. 사업계획의 기준 표와 산출 설명에서 측정 대상·기간·분자/분모·단위·집계/반올림·원시 근거를 찾아 주장에 연결하고, 개선 조치가 어느 지표와 어떤 관계인지 정리한다. 검토본의 과거 실측 주장과 계획 기준값은 시점·대상·계산 조건별로 유지한다. 값이 다르다는 이유로 하나를 버리거나 같은 조건인지 확인하기 전에 오류로 확정하지 않는다. 자세한 주장 필드는 [evidence-contract.md](evidence-contract.md)를 따른다.

한 과제의 분석 결과를 재사용 규칙으로 바꿀 때에는 실제 기업·기능·수치·오류 사례를 제거하고 판단에 필요한 일반 원칙만 남긴다. 원사업 값의 익명화본을 합성 예제로 공개하지 않는다.
