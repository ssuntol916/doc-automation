# 품질 게이트

현재 실행 계약은 repo `docs/OUTPUT_QUALITY.md`와 `schemas/quality-review.schema.json`을 읽는다. `scripts/run.py qa-paths`가 관련 자원의 실제 경로/존재를 출력한다.

## 서로 다른 판정

- 양식·검토 반영: 기준본의 전체 표·열·병합·고정 항목과 사용자 직접 수정이 유지되고, 요청한 위치의 피드백만 반영됐는가. `scripts/check_form_preservation.py`의 구조 대조와 텍스트 소유 위치 검사를 함께 사용한다. 이 판정은 생성물의 구조 검사나 PDF 가독성 통과로 대체하지 않는다.
- 구조와 허용 서식: 번호·소제목·항목 순서·내용의 절 귀속·셀 주소·병합은 보호하고, 허용된 타이포그래피·문단·쪽 흐름 변경은 별도 목록으로 대조한다. 위 스크립트는 페이지 제어·앵커·반복 머리행도 비교하므로 허용된 쪽 흐름 조정에서 차이가 날 수 있다. 차이 경로별로 명시한 편집인지 확인하고 행·열·셀·병합·고정 문구 검사는 따로 통과해야 한다. 전체 원문 속성 일치나 자동 검사 통과가 극소 글씨·낮은 대비·기울임 오용·제목용 본문 글꼴을 정당화하지 않는다.
- 패키지: ZIP/XML과 spine·참조·개체·표 구조가 유효하고 원본이 보존되었는가.
- 공통 사실: 출처 SHA/위치, 도메인 ID와 참조, 기간·기업 역할·합계·단위·산식·미확인 상태가 일관되는가.
- 네이티브: 현재 출력 HWPX를 실제 한글에서 열고 출력·렌더·육안 검토했는가.
- 사업 제출: 실제 사실·수행·승인·서명·첨부와 담당 검토가 해당 요청 범위에 충분한가.

앞 단계의 통과를 다음 판정으로 자동 승격하지 않는다. `validate-project`의 draft_ready와 submission_ready, `verify-output`의 passed는 다른 결론이다.

## 선택 프로필의 검증 경계

`reference-v1`의 코드·프로필·기계 회귀는 서식 적용 기능의 근거다. 이 갱신 시점의 새 프로필 전체19종에 대한 참고 수준95%·최종 native 편집 적합성은 아직 pending이며, 현재 출력별 증거와 미검토를 확인해야 한다. 기존 reviewed-suite의 과거 해시/PDF·279회귀 또는 새 focused 회귀를 새 출력의 스타일 합격으로 승계하지 않는다.

세 경계를 나누어 검토한다.

1. 원자료/양식→내용 구성: 모든 제공 의미 필드의 값·타입·ID·방향·관계·notes·상태·source_refs를 본문/근거표/부록 위치에 대응한다. raw JSON을 문장·표로 바꾼 텍스트 차이는 의도한 변환으로 기록하되, 부속 JSON이 존재한다는 사실만으로 문서의 의미 누락을 면제하지 않는다. `false/0/null/빈문자열`과 미확인·미수행의 구별을 확인한다.
2. 내용 구성→서식 적용: 정확한 profile path/SHA·source SHA·역할·허용 변경·selector·실제 값을 비교한다. 7script fontface, 크기, 자간/장평, 모든 lineSpacing 분기, 표 전체/열/병합폭/여백, 새 구역·그림 연결을 확인한다. 등록된 `reference-v1` CLI 표지 프로필에서는 명시한 다섯 owner의 font/height/bold와 별도 선언한 program 문단의 breakNonLatinWord 외 페이지·표·셀·문단 서식·개체·제어를 유지한다. 원본 XPath/own text·문단 정의와 registry가 일치하는지, 부모 customer 서식이 자식 program/title에 번지지 않았는지 확인한다. 고정 문구·허용 범위 밖 개체·셀 소유권은 유지되어야 한다. 문구와 줄바꿈 변경에 따른 native 상자 높이·후속 문단 위치 변화는 XML 기하 보존과 구분하여 관측한다.
3. 서식 적용→native 저장: 선택한 서식 적용이 끝난 현재 bytes를 strict 기준으로 삼는다. 이후 한컴이 폰트·fallback·간격·표·그림·구역을 바꾸면 프로필에서 허용한 의도 변경으로 면제하지 않는다. 정확한 제한 복원과 복원 최종 bytes의 새 검토 절차는 기존대로 유지한다.

서식 적합성은 실제 PDF/전쪽 이미지에서 제목·라벨·값의 위계, 글꼴 대체, 읽기 크기, 긴 ID, 계속 표의 문맥, 큰 공백, 그림 식별력을 비교한다. 1x1 서술 frame을 표머리로 꾸미거나 카드의 입력값 전체를 라벨처럼 강조하지 않는다. 구역을 나누면 목차 제목/항목 분리와 쪽번호 재시작을 확인하고, floating 표 여러 개와 그 뒤 고지/본문의 출력 순서·완결 여부를 대조한다. 기계 점수로 중요한 누락·충돌을 상쇄하거나, 원본의 좁은 여백/조밀함을 성공 규칙으로 학습하지 않는다.

## 현재 바이트를 검토하는 방법

현재 HWPX와 입력/양식 해시를 고정한다. 실제 앱 이름·버전·빌드, 열기/복구/상위버전 안내, 한글에서 내보낸 PDF 해시를 기록한다. PDF의 모든 페이지를 Poppler 등으로 렌더하고 각 PNG의 해시·페이지 번호를 보존한다. 모든 페이지의 검사/시각검토 상태와 검토자·시간·한계를 작성한다. contact 훑기와 확대 원페이지 검토 범위를 구분한다.

각 페이지에서 표/글자의 잘림·충돌·넘침·읽기 크기·반복 머리행·이미지 식별력·머리말/꼬리말·쪽번호/목차·샘플 잔존·합성/미수행 고지를 확인한다. 긴 표와 작은 증적은 필요한 원페이지를 확대한다. 좌표 검사나 PDF 텍스트 추출만으로 육안 검토를 대체하지 않는다.

좁은 구분·날짜·담당자·비고 칸에 긴 상태 고지와 원시 출처를 반복하면 내용이 XML에 존재해도 읽기 어려워진다. 칸의 의미에 맞는 짧은 값과 명시적인 참조 키를 사용하고, 전체 값·출처·미확인 상태는 연결된 넓은 상세 영역에 보존한다. 선택한 본문 읽기 크기를 임의로 줄이거나 근거를 생략해 해결하지 않는다. 고정된 부유 표가 한 쪽보다 커지면 글자가 PDF에서 잘릴 수 있으므로 전체 내용과 뒤따르는 본문 순서를 실제 출력에서 대조한다. 쪽 분할·앵커 변경은 해당 프로필의 명시적 수정으로 다루고 새 출력 검증 전 성공으로 간주하지 않는다.

검토 기록은 `verify-output REVIEW.json --input INPUT.json --template TEMPLATE.hwpx --report RESULT.json`으로 현재 입력·양식·HWPX·PDF·전체 PNG와 대조한다. 저장·수정해 HWPX가 바뀌면 그 바이트에서 다시 출력하며 영향받는 검토를 갱신한다. 실제 편집/저장 시험을 하지 않았다면 단순 열기 성공과 구분한다. 기록에 앱 이름이 적혔다는 사실은 실제 실행이나 검토 판단의 진위 증명이 아니다.

목차는 실제 상세 카드/절의 인쇄 쪽수를 현재 PDF에서 찾아 갱신한다. 메뉴나 고지의 첫 ID 언급을 상세 카드 위치로 오인하지 않는다. repo `docs/TOC_FINALIZATION.md`와 `scripts/finalize_toc.py`의 해시 연결·재출력 절차를 따른다. 한글 재저장 후에도 그 최종 바이트에서 내보낸 PDF로 다시 측정하고, 현재 목차 문구가 실측과 같아 추가 변경이 필요 없는지 확인한다. `쪽수 확인 예정`이나 옛 샘플 쪽수를 확정 목차처럼 남기지 않는다.

목차가 현재 인쇄쪽과 일치해도 인쇄쪽 자체가 중복·역행할 수 있다. 구역별 재시작의 의도와 실제 순서를 별도로 확인한다. 지침 텍스트를 지울 때 남은 PAGE 재시작, 원래 목차 후미에 붙은 본문 번호 앵커를 살핀다. 전체 제어를 일괄 제거하거나 원본을 수정하지 않는다.

재저장 전후에는 `scripts/audit_generated_roundtrip.py --before BEFORE.hwpx --after AFTER.hwpx --output REPORT.json`으로 텍스트·셀 소유권·실제 사용 글꼴/문단 정의·필드/수식/그림 연결·구역/표 기하를 독립 대조할 수 있다. `scripts/audit_generated_roundtrip.py`의 정규화 범위와 `tests/test_compose.py`의 음성 대조를 확인한다. 과거 실행 검토는 로컬 `verification/generated/roundtrip-review.md`에 있다. 이 정적 통과도 실제 인쇄 내용·전체 페이지 시각 검토를 대신하지 않는다.

한글이 재저장 때 동일 테두리 정의를 합치고 참조 ID를 바꿀 수 있다. 표·셀의 `borderFillIDRef` 숫자 차이와 실제 테두리 색·굵기·형식 변화를 구분해 해결한 정의로 비교한다. 미해결 참조나 실제 정의 변화는 숫자 재배치로 면제하지 않는다. 전후 보존 검사는 그 이전 목차 편집에서 이미 사라진 내용을 탐지하지 못하므로 입력→생성→목차→native 각 경계를 확인한다.

Save As에서 `substFont`가 소실되면 이를 ID 정규화나 허용 가능한 글꼴 변화로 처리하지 않는다. 정확한 원문 선언의 제한 복원 조건은 [package-editing.md](package-editing.md)를 따른다. 일반 `open/save_as/close/reopen/export_pdf`와 다른 `native_save_repair_reopen` 경로를 repo `docs/NATIVE_EVENTS.md`에 따라 명시한다. 실제 저장 중간물 `native_saved`와 복원 최종물 `native_after`는 서로 다른 path/SHA로 남긴다. 실제 여덟 사건 `open → save_as → close_saved → package_postprocess → open_final → close_final → reopen → export_pdf`의 대상 artifact·시간·관찰과 복원 report를 연결한다. 복원된 현재 바이트의 열기·닫기·재열기·PDF·전쪽 검토·TOC·독립 서식 검사를 모두 수행한다. 중간 저장물의 PDF나 과거 native 판정을 최종물에 승계하지 않으며, 복원물은 한컴 Save As 그대로라고 보고하지 않는다. 다시 Save As했다면 fallback과 새 바이트를 다시 검사하고 출력 QA를 갱신한다. PM3에서 관찰한 선언11개 소실은 해당 환경의 한계이며 문서별 예외나 성공 스타일이 아니다.

PDF 추출에서 문구가 없더라도 실제 글리프가 보일 수 있고, 전역 검색에 있다고 올바른 카드에 있다는 뜻도 아니다. 반복 제목 때문에 고유 위치를 못 찾으면 보조 검사를 미확정으로 남기고 각 카드의 원본 페이지와 소유 문단을 직접 대조한다. 머리행 누락처럼 보이는 관찰도 해당 원페이지를 다시 읽어 확인한 뒤 결함으로 기록한다. 관찰 오류와 실제 생성 결함을 구분한다.

## 불일치 처리

원본 오류, 지원 환경의 호환성 한계, 생성기가 만든 결함, 아직 원인이 확인되지 않은 관찰을 구분한다. 예전 원본의 PDF나 과거 앱 버전 결과를 현재 생성물 검토로 재사용하지 않는다. 이 코퍼스의 기준 출력 환경은 `verification/baselines/native-environment.json`에 있으며 새 작업의 실제 버전을 대신하지 않는다. 과거 표 머리행 누락·잔여 머리말·작은 증적·상위버전 안내는 성공 스타일로 학습하지 않는다.

미검토·실패·원인 미확인 항목은 기록하고 수정 후 해당 출력 범위를 다시 확인한다. 실제 검토하지 않은 범위를 passed로 채우지 않는다. 합성·참고추출 자료는 기계 검사와 출력 검토를 통과해도 실제 제출 가능 상태가 아니다.
