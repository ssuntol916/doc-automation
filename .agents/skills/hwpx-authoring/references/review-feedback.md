# 사용자 검토본의 보존과 피드백 반영

사용자가 검토본·수정본을 제공했거나 이전 수정 사항의 재발 방지를 요청한 경우에 읽는다. 스킬의 원형 보존 원칙과 현재 사용자의 편집 요청을 함께 적용한다.

## 기준본과 실제 검토 범위

원래 양식, 이전 작성본, 사용자 검토본을 구분하고 각각 SHA-256을 기록한 사본에서 비교한다. 여러 검토본은 문서 역할·버전별로 이전본과 검토본을 짝짓고 모든 OPF 구역과 전체 반복 항목의 대응·누락을 확인한다. 원본과 검토본을 덮어쓰지 않는다. 검토본에 사용자가 이미 수정한 제목·사업장 표기·공란·문체·서식과 열폭·문단 분리·정렬을 다음 편집의 기준으로 삼는다. 이전 템플릿이나 초안에서 다시 만들어 되돌리지 않으며, 특정 표의 폭 수정을 다른 표의 임의 폭 변경 권한으로 확대하지 않는다.

이전 작성본을 식별할 때 현재 전달 폴더의 파일명만 믿지 않는다. 보존된 생성본·당시 manifest·전달 ZIP이 있으면 SHA를 대조하고, 이미 수정된 전달 사본은 별도 중간본으로 구분한다. 해시가 다르다는 사실만으로 수정 주체나 시점을 단정하지 않는다. 비교 원장에는 어떤 바이트를 이전 작성본으로 삼았는지와 그 근거를 남긴다.

다음 세 종류를 별도 원장에 남긴다.

- 직접 수정: 추가·대체·삭제·서식 변경이 이미 완료된 편집. 그대로 유지할 대상이다.
- 작성 지시: 본문 표식, 메모 또는 변경 추적이 요구하는 추가 작업. 지시문 자체를 제출 본문에 남기지 않는다.
- 확인 사항: 목표·수치·사실·적용 범위의 확인 요청과 검토 후 남은 ID·값·범위의 불일치. 검토본에 있다는 이유로 불일치를 해소된 사실로 확정하거나 근거가 없는 값을 만들어 지시를 없애지 않는다.

각 짝의 실제 메모/변경 추적도 읽는다. 그림의 `shapeComment`, 비어 있는 취소선 run, 저장 시 바뀐 ID·자동 방향 속성을 사용자 피드백으로 오인하지 않는다. 문자·문단·테두리는 파일 내부 ID가 아니라 실제 참조 정의와 적용된 값을 비교한다.

한 문단이 여러 문단으로 나뉜 변경은 공백을 정규화한 텍스트와 원문의 문단·줄바꿈·서식·셀 소유권을 함께 비교하여 내용 추가·삭제와 구별한다. 정규화는 대응 분석용이며 검토본의 실제 경계를 지우는 편집 방법이 아니다. 이어진 문장·목록은 같은 의미 단위에 연결하고, ID 목록의 순서와 전체 항목도 대조한다.

별도 메모가 없어도 본문 안의 표식·화살표·요청 문구와 새로 나눈 입력 라벨을 읽는다. 반복 블록에 추가된 빈 라벨은 작성할 정보의 구분을 지시할 수 있으므로 값이 비었다는 이유로 삭제하거나 기존 포괄 설명으로 덮지 않는다. 지시의 수행 여부는 표식 제거가 아니라 각 라벨에 대응하는 내용·근거로 확인한다.

수정이 확인된 절과 명시된 반영 범위를 기록한다. 일부만 검토한 문서를 전체 승인으로 간주하지 않는다. 같은 피드백의 적용 범위가 현재 요청에 포함되면 그 범위의 동일 유형을 함께 고치되, 관련 없는 본문·양식 전체를 재편집하지 않는다.

## 편집과 반영 원장

원형 유지 대상과 허용 편집을 먼저 나눈다. 항목 번호·소제목·항목 순서·내용의 절 귀속과 표의 행·열·셀·병합·작성 주체 구분은 고정한다. 글꼴·서식·줄 간격 정리가 허용되면 제목과 본문 소유 위치를 바꾸지 않고 타이포그래피를 개선한다. 예를 들어 한 절의 내용을 다음 번호 아래로 이동하여 배치 문제를 해결하지 않는다.

줄바꿈·시작선·블록 여백의 피드백은 해당 텍스트·그림의 실제 소유 문단에 한정해 적용한다. 자동 줄바꿈을 우선하고 필요한 절 경계만 개행하며, 같은 수준의 본문 후속 줄은 공통 왼쪽 기준에 맞춘다. 번호·글머리 목록의 의도된 내어쓰기와 제목·인용의 들여쓰기는 보존한다. 소제목·본문·그림·캡션 사이의 구분은 문단 앞·뒤 간격을 우선 검토하되 고정 빈줄 개수나 pt 값을 일반화하지 않는다. 이 편집만 요청받았다면 기존 글꼴·크기·줄 간격·강조, 표 구조·열폭과 하위 절의 전체 내용은 유지한다. 그림·표·제어를 담은 문단을 일반 텍스트로 덮거나 해당 절 밖의 배치를 일괄 변경하지 않는다.

입력 예시나 빈 문단의 문자 속성을 작성 내용에 그대로 상속하는 것은 원형 보존의 필수 요건이 아니다. 실제 사용 글꼴·크기·굵기·기울임·색·자간·장평·정렬·들여쓰기·문단 간격을 해결해 제목·본문·표 머리·값·주석·도식 라벨 역할로 적용한다. 보통 본문 전체가 제목용 글꼴이나 굵은 글씨가 되거나, 표 값 전체가 예시용 파랑·연회색 기울임이 되지 않게 한다. 어두운 채움의 표 머리에는 대비되는 글자색을 유지하고, 도식의 극소 공백 문단을 일괄 본문 크기로 키워 표를 늘리지 않는다.

허용된 서식 변경과 구조 보존을 별도 검사한다. 글꼴 ID나 모든 문단 속성이 원본과 같다는 이유로 읽기 어려운 결과를 합격시키지 않는다. 반대로 선언된 글꼴·문단·쪽 흐름 차이를 셀 추가·제목 변경과 같은 구조 위반으로 취급하지 않는다. 쪽 흐름을 바꿨다면 고정 라벨·번호·원문 텍스트 소유권, 셀 주소·병합·열폭을 독립 대조하고 현재 출력의 행 완결과 반복 머리행을 확인한다.

각 피드백에 기준 SHA, XML 소유 위치, 원문 지시, 의도, 새 내용, 근거 위치, 반영 상태와 확인 결과를 연결한다. 실제 사업의 원문과 경로·이미지는 비공개 작업공간에 보관한다.

사용자가 ID를 직접 수정하면 원문 ID→새 ID의 대응을 기록한다. 문서 전체의 목차·본문·내부 참조와 관련 산출물이 가리키는 대상 ID·명칭·의미의 일관성을 검사한다. 접두어가 비슷하다는 이유로 미검토 항목을 자의적으로 치환하거나 일괄 재번호하지 않는다. 남은 옛 ID나 문서 간 차이는 해당 항목의 근거·검토 범위에 따라 반영하거나 미해결로 기록한다.

표가 들어 있는 외곽 문단이나 그림·필드·제어를 일반 텍스트로 덮지 않는다. 표 안에 여러 문단으로 사용자가 나눠 놓았다면 제목과 본문 소유 문단을 각각 수정한다. 셀 전체를 다시 쓰며 사용자 서식·빈 문단·개체를 없애지 않는다.

사용자가 공란으로 만든 특정 입력 칸에 자동으로 `확인 필요`를 다시 채우지 않는다. 표시상 공란과 사실 모델의 미확인을 구분하며 공란을 미참여·미수행·0으로 확정하지 않는다. 이 선택을 다른 미확인 칸 전체의 삭제로 확대하지 않는다.

사용자가 직접 제거한 빈 반복행·미확인 안내 그림도 검토본의 실제 변경으로 기록한다. 이후 작업은 이 검토본을 기준으로 하여 지운 행·그림을 자동 복원하지 않는다. 특정 표의 빈행 삭제를 모든 서식의 행 삭제 권한으로 확대하지 않으며, 도식의 빈 상자 정리 지시도 해당 도식에 한정한다. 보호할 원양식과 사용자가 직접 바꾼 기준본의 차이를 모두 보존 원장에 남긴다.

도식의 빈칸 정리는 배치용 공백·미사용 노드·입력칸 중 실제 대상을 구별해 수행한다. 비어 있다는 이유만으로 기능·연결선·그룹 경계나 고정 입력칸을 함께 삭제하지 않는다.

사용자가 제거한 내부 출처 코드·작성 과정 고지·불필요한 캡션을 재삽입하지 않는다. 출처 SHA·위치·검토 상태는 원장에 계속 보존한다. 법정 고정 문구·필수 안내·서명·합성 고지처럼 별도 의미나 요건이 있는 내용은 일반적인 내부 메타 설명과 구별한다.

검토본에서 의도적으로 비운 출처 칸에도 이전 문구를 자동 복원하지 않는다. 공란의 표시 선택과 근거 연결은 별개이므로 실제 출처는 비공개 원장에 유지한다. 목록·명세 그림과 서명 그림은 payload뿐 아니라 카드·셀·소유 문단, 표시 크기·비율·crop·연결 관계를 기록하여 같은 위치에서 보존한다. 기존 서명 그림을 보존하는 것과 새 카드·새 프로젝트에 서명을 옮겨 승인 근거를 만드는 것은 구별하며, 기존 그림을 다른 서명·승인에 재사용하지 않는다.

## 반영 확인과 다음 작업의 규칙

편집 전 기준본과 출력물을 `scripts/check_form_preservation.py`로 비교한다. 표 개수만 같다는 것으로 열·병합·너비·셀 소유권의 보존을 대신하지 않는다. 원형 검사는 사용자 검토본을 기준으로 한 이번 편집과 원래 양식 대비 전체 복원 여부를 구분한다.

허용된 텍스트 위치의 전후 값과 나머지 문단·그림·표의 보존을 별도로 확인한다. 내부 피드백 표식이 사라진 사실만으로 요청이 충족됐다고 판단하지 않는다. 현재 HWPX에서 다시 출력한 PDF에서 새 내용의 완결, 실제 줄 수, 표 안팎 위치와 뒷부분 밀림을 확인한다.

수작업 점채움 목차는 제목·대상 절과 현재 출력의 쪽번호를 대조하고 쪽번호 열의 정렬을 확인한다. 목표는 읽을 수 있는 대응과 정렬이며, 고정 점 개수나 이전 쪽번호를 복사하는 규칙이 아니다.

그림·행·반복 안내를 삭제한 경우 그 대상을 가리키던 문장·캡션·번호가 남았는지 확인한다. 저장 후 생긴 명시적 `NONE` 장식 속성·ID 재배치·사용하지 않는 이미지 정리와 실제 가시 서식 수정을 구별한다. 이 구별은 native 저장 보존 검사에서 실제 정의 손실을 면제하는 규칙이 아니다.

사용자가 실제로 수정한 사실과 그 결과의 품질·검증 상태를 분리한다. 동일 그림 SHA라도 표시 비율·crop·렌더링 행렬이 바뀔 수 있으므로 따로 대조한다. 그림 비율 왜곡·잘못 삽입된 캡처·잔여 옛 ID를 긍정적인 작성 규칙으로 학습하지 않는다. 수동 단어 분할·빈줄 개수·`keepLines`/`keepWithNext` 해제나 임시 쪽 나눔도 모든 문서에 적용하지 않는다. Native 출력이 미검토인 경우 변경 관측만 기록하고 레이아웃 합격을 선언하지 않는다.

기존 카드의 문장·서식이 그대로이고 새 카드만 추가됐다면 기존 부분까지 문장·글꼴·줄바꿈이 개선됐다고 보고하지 않는다. 추가 카드의 다른 글꼴·줄간격, 그림 삽입 후 재계산된 표 전체 높이, 저장 과정의 자동 방향 정규화는 각각의 관측으로 남긴다. 이를 모든 카드의 글꼴 교체·셀 높이 증가·속성 강제 변경 규칙으로 승격하지 않는다.

일반화할 수 있는 피드백은 해당 스킬의 관련 절에 반영한다. 특정 사업의 목표·기업명·본문을 공개 스킬에 넣거나 한 번의 스타일 관측을 모든 문서의 규칙으로 만들지 않는다. 재발 원인이 구조 변경이라면 독립 합성 입력으로 정상 채움 통과와 열·병합·표 구조 변경 차단을 확인한다. 형식 검사 통과와 스킬의 실제 행동 검증은 구분한다.
