# 참고자료 수준의 HWPX 작성 스킬 개선 계획

공개 checkout에는 실제 사업 원문·참고 파생 입력·과거 native 검토 이력이 포함되지 않는다. 아래 과거 관측은 비공개 로컬 이력이며 새 출력 판정이 아니다. 현재 개선 반복은 중단 상태다. 원본 연결과 공개/비공개 경계는 [PRIVACY.md](PRIVACY.md)를 따른다.

작성일: 2026-10-24. 상태: 계획 보고, 개선 작업 미실행.

목표는 참고자료에서 유효한 글꼴·문단·표·그림·페이지 편집 방식을 추출하고, 이를 새로운 사업 데이터에도 적용하는 HWPX 작성 능력을 확보하는 것이다. 파일이 정상적으로 열리고 내용이 보존되는 것에 더해, 독자가 내용을 읽고 비교하고 판단하기 좋은 결과를 만들어야 한다.

이번 보고에서는 계획서만 작성한다. 현재 생성기·스킬·원본 자료·`reviewed-suite`의 HWPX/PDF와 기존 검토 기록은 변경하지 않는다. 아래 산출물과 검증은 앞으로 수행할 작업이며, 이미 완료한 결과가 아니다.

## 현재 상태와 목표의 차이

현재 기준은 검토 완료 합성 예제19종 (로컬 자료: `generated/reviewed-suite/README.md`), [양식과 참고자료 비교](../resources/stage2/analysis-design-comparison.md), 실사용 서식 비교 자료 (로컬 자료: `analysis/stage2/analysis-design-evidence/format-comparison.json`)다. 참고자료는 한 전문가가 작성한 한 사업의 문서이며, 그 사업의 사실이나 모든 편집 선택을 보편 규칙으로 만들지 않는다.

| 관점 | 현재 차이 | 이번 개선의 목표 |
|---|---|---|
| 글꼴과 위계 | 참고 본문은 주로 함초롬바탕10~11pt, 현재 예제는 바탕체10~12pt 중심이며 역할별 글꼴이 혼재 | 제목·소제목·라벨·본문·식별자·주석별로 선택한 서식을 일관되게 적용 |
| 줄간격과 문단 | 현재는160% 중심, 참고는 설명·표·제목에 따라100~200% 혼용 | 문단 역할과 정보 밀도에 맞춘 간격·들여쓰기·강조 규칙 적용 |
| 용지와 표폭 | 참고 TD3·TD5 상세는 가로 구역을 사용하지만 현재 예제는 세로 표를 유지 | 내용에 맞는 구역 방향·열폭·셀 여백으로 긴 ID와 설명을 읽기 좋게 배치 |
| 줄바꿈과 페이지 | 현재 TD5의 긴 ID가3~4줄로 갈라지고 행높이가 커짐 | 내용 보존과 함께 단어·행·카드·페이지의 읽기 흐름을 설계 |
| 본문 표현 | 타입·null·출처 경로·추적 JSON 등 기계 표현이 본문에 많이 노출 | 업무 문장과 명세표로 작성하고, 필요한 기술 정보와 검증용 정보를 구별 |
| 그림과 화면 | 현재 생성기는 제공된 화면·도식 첨부의 삽입을 지원하지 않아 생성 전 거절 | 의미가 확인된 화면·도식을 본문·캡션·설명과 연결하여 삽입·검토 |
| 검증 기준 | 현재279회귀와 출력 검토는 보존·정합성·출력 안정성의 근거 | 기술 검증과 별도로 참고 수준의 편집 적합성을 판정 |

참고의 우측1.55mm 같은 극단적인 여백, 컬럼명/ID 전치, 미완성 문장, 설명되지 않은 표시 등은 자동 채택하지 않는다. 관찰값과 실제 적용할 목표값을 구별한다. 참고와 픽셀 단위로 같거나 쪽수가 같다는 사실도 목표 수준의 충분조건이 아니다.

## 개선 범위와 판단 원칙

우선 현재 지원하는 정부지원사업 개발산출물19종을 대상으로 한다. 네 파일럿은 방법을 검증하기 위한 선행 작업이며, 네 종류만 개선한 것을 전체 완료로 보고하지 않는다. 독립34서식은 분석·작성 지침 자원으로 활용하고, 전체34서식의 생성 지원은 이 계획과 별도 범위로 둔다.

선택한 양식의 필수 필드·기재 지침과 사업 사실을 유지하면서 참고자료의 유효한 편집 관행을 적용한다. 원본에 서식이 존재한다는 이유만으로 모든 글꼴·폭·방향을 절대 고정하지 않는다. 필수 요건인지 기본 모양인지 확인하고, 바꿀 항목은 선택한 서식 프로필에 명시한다. 양식의 강제 요건과 충돌하는 관행은 근거와 함께 제외하거나 보류한다. 실제 사업의 현행 제출 요건은 해당 사업 자료로 따로 확인한다.

모든 규칙에는 다음을 구분해 남긴다.

- 양식의 명시 지침: 원본 SHA와 XML 위치.
- 전문가 관행: 참고 SHA, 실제 사용 run·문단·표·구역 위치와 대응 PDF쪽.
- 사업 사실: 제공한 데이터와 출처.
- 편집 선택: 채택한 목표값, 적용 범위, 선택 사유.
- 미확인: 상충하는 지침, 부족한 자료, 아직 검증하지 않은 동작.

|---|---|---|---|

| 2. 서식 프로필 설계 | 제목·본문·표머리·라벨·값·주석·그림·구역별 서식을 실제 수치와 적용 위치로 정의 | 버전이 있는 역할별 서식 프로필, 허용 변경 명세 | 숫자형 서식 ID에 의존하지 않고 대상·목표값·변경 범위를 결정할 수 있음 |
| 3. 본문 구성과 문체 설계 | 원자료를 업무 문장·명세표·근거표에 배치하고 JSON 직접 출력과 반복 안내를 정리 | 입력 필드→본문/부록 위치 대응표, 작성 예, 미제공 자료 처리 규칙 | 독자에게 필요한 정보가 읽히고, 값·타입·관계·출처·불확실성의 의미가 손실되지 않음 |

### 단계 1과 2에서 고정할 서식 명세

프로필은 문서 전체에 하나의 폰트와 줄간격을 강제하는 방식으로 만들지 않는다. 최소한 다음 역할을 구별한다.

- 표지, 목차, 장·절 제목, 일반 설명, 번호 절차.
- 표 머리행, 필드 라벨, 일반 값, 물리 ID·코드·수치·단위.
- 그림·표의 번호와 캡션, 출처 주석, 미확인 상태 안내.
- 세로/가로 구역, 본문·표·그림의 허용 폭, 표 안쪽 여백, 계속 쪽 머리행.

각 항목에는 원본·참고 SHA와 위치, 의미 역할로 식별한 대상, 관찰값, 선택한 목표값, 허용 변경, 적용 조건, 예외, 버전, 검토 상태를 기록한다. 예를 들어 특정 요구사항 카드 본문에 함초롬바탕10pt·130%를 선택하더라도 다른 역할에 그대로 전용하지 않는다. 한글·영문·숫자·기호의 글꼴 참조와 대체글꼴을 확인하며, 실제 글꼴 대체 여부는 선언값과 최종 PDF의 글꼴을 함께 확인한다.

### 단계 3에서 정리할 본문

PM4의 추적 JSON은 요구사항·연결 대상·방향·관계·검토 상태·근거를 읽을 수 있는 표와 문장으로 바꾼다. TD5는 논리명·물리 ID·타입·키·기본값·NULL·암호화·제약을 일정한 위치에서 비교하게 한다. TD3는 필드명·형식·필수 여부·기본값·검증 조건을 괄호 문자열의 반복 대신 읽기 좋은 명세로 구성한다.

DB 타입·물리 ID처럼 업무상 필요한 기술 정보는 본문에 남긴다. 내부 JSON Pointer·디버깅 상태·자동화 추적 정보는 독자가 사용할 근거표·부록과 기계용 부속으로 배치한다. 원시 JSON을 그대로 부록에 옮기는 것만으로 작성 품질을 충족했다고 보지 않는다. 제공한 의미 필드마다 문서 내 확인 위치나 출력하지 않는 명확한 사유가 있어야 한다.

`false`, `0`, `null`, 빈 문자열과 값의 타입, 연결 방향·관계·notes·source_refs는 이 과정에서도 유지한다. 미확인을 미수행·선택·비기능·미적용으로 바꾸지 않는다. 문장을 자연스럽게 만들기 위해 제공하지 않은 사실이나 승인·결과를 채우지 않는다.

합성 고지는 문서 안에 유지하되, 같은 경고를 좁은 모든 셀에 반복하지 않는다. 문서 수준 고지와 해당 항목의 상태를 구분해 배치한다.

### 단계 4의 구현 범위

현재 [compose.py](../src/doc_automation/compose.py)의 원본 보존·정의 파생 패턴을 활용한다. 먼저 필요한 작은 기능부터 추가하고, 범용 레이아웃 엔진 전체를 새로 만드는 작업으로 확대하지 않는다.

| 기존 위치 | 필요한 보완 |
|---|---|
| `compose.py` | 원정의를 유지한 글꼴·크기·강조·문단 간격 정의 파생과 대상 run/문단 재연결. 구역 생성·방향 전환, 표 전체폭/셀폭/병합폭/여백의 일관된 변경 |
| `renderers.py` | 역할별 프로필 선택·적용, 본문/근거표 표현, 긴 식별자 처리, 제공된 이미지의 의미 슬롯 매핑 |
| `toc.py` | 세로·가로 구역과 반복 카드 변경 후 실제 제목·카드 위치와 최종 쪽수 재측정 |
| `quality.py` 및 검토 절차 | 현재 기술 검증을 유지하고 서식 적합성·편집 검토를 별도 근거로 연결 |
| 두 canonical 스킬 | 기계적 편집 방법과 도메인 작성·문체·프로필 선택을 각 책임에 맞게 안내 |

그림은 TD3의 표준 시안·기존 화면·변경 화면 슬롯부터 지원한다. 첨부 ID·SHA·출처·설명·원본 비율·크롭·합성 여부와 대응 화면 ID를 연결한다. 기존 그림 교체 기능만으로 새 그림 삽입과 의미 연결까지 지원한다고 보고하지 않는다.

## 의도한 내용 및 서식 변경과 보존 검사의 관계

비교 경계를 세 개로 나눈다. 업무 표현을 재작성하는 구간과 이미 작성한 내용을 조판하는 구간의 보존 기준을 혼동하지 않는다.

1. **원자료·양식 사본→내용 구성 결과:** 입력 필드·타입·ID·관계·상태·출처와 문서 내 확인 위치를 대응시켜 의미의 누락·왜곡을 검사한다. JSON을 업무 문장·표로 바꾸거나 본문과 부록으로 나누는 의도한 텍스트·위치 변환을 기록한다. 이 구간에 원시 JSON 문자열과 작성 문장의 완전 일치를 요구하지 않는다. 양식의 변경 대상 밖 개체·고정 문구·제어는 계속 보존한다.
2. **내용 구성 결과→서식 적용본:** 작성한 텍스트·의미·ID·개체 연결을 유지하며 선택 프로필의 글꼴·간격·열폭·구역 변경을 실제 값으로 확인한다. 구역 이동 등으로 위치가 바뀌면 선언된 대상·새 소유 위치를 확인하고, 허용 변경 밖 내용·서식·셀 소유 관계는 정확히 보존한다.
3. **서식 적용본→한컴 저장본:** 이 단계의 의도하지 않은 서식·내용 변화는 실패로 처리한다. 이미 목표 서식을 적용한 현재 바이트를 기준으로 strict 보존 검사를 유지하며, 서식이 달라졌다는 이유로 기존 검사를 전역 완화하지 않는다.

이는 검증 논리의 경계다. 매 구간마다 별도 HWPX를 의무적으로 만드는 대신 필요한 모델·스냅샷·변환 내역으로 해당 경계의 검사를 재현할 수 있게 한다.

서식 ID는 파일마다 새로 해결하며 다른 파일의 숫자를 복사하지 않는다. 새 구역은 첫 문단의 구역 제어, OPF spine, 머리말·꼬리말·쪽번호·표지 숨김·개체 앵커까지 함께 확인한다. 표폭 변경은 열폭 합·병합 셀·셀 여백과 사용 가능한 본문 폭을 함께 맞춘다. 긴 문단 전체를 keep으로 묶거나 빈 문단·스페이스·강제 개행으로 위치를 맞추지 않는다.

PM3에서 관찰한 대체글꼴 소실 같은 native 한계는 정확한 정의 복원과 실제 최종 바이트 재검토 절차를 유지한다. 출력되지 않은 최신 파일을 이전 PDF나 다른 렌더러 결과로 통과시키지 않는다.

## 파일럿 네 종류와 검증 순서

| 순서 | 문서 | 먼저 확인할 개선 | 파일럿에서 제공할 비교 결과 |
|---|---|---|---|
| 1 | AD2 요구사항정의서 | 글꼴·역할별 간격·번호 절차·카드 높이·짧고 긴 내용의 배치·분류별 목차 | 참고/현재/개선본의 같은 내용 카드, 짧음·보통·장문 카드와 계속 쪽 |
| 2 | TD5 DB설계서 | 세로 목록/가로 상세, 열폭·식별자 줄바꿈, 머리행, 기본값·제약·출처의 읽기 순서 | 긴 ID와 한글명이 있는 표, 계속 쪽, 모든 의미 필드의 확인 위치 |
| 3 | TD3 화면설계서 | 화면 이미지와 명세 대응, 가로 구역, 필드·버튼·권한·검증 조건의 표현 | 제공 이미지 사례와 명시된 합성 시안 사례, 이미지 없는 입력의 보류 표시 |
| 4 | PM4 요구사항추적표 | 넓은 추적표, 원시 JSON의 업무 표현 전환, 핵심 연결과 상세 근거의 구분 | 기능·비기능·미확인 요구와 직접/명시 연결, 원문 의미 보존 대응표 |

AD2로 서식 적용의 기본 동작을 먼저 안정화하고 TD5에서 가장 뚜렷한 표·줄바꿈 문제를 검증한다. TD3에서는 그림과 구역, PM4에서는 본문 작성과 의미 보존을 검증한다. 각 파일럿의 원본 참조와 작성 목적은 분리해 적용한다.

첫 중간 보고에는 AD2·TD5의 대표 본문을 참고/기존/개선본으로 나란히 보여주고 채택·제외한 규칙과 남은 차이를 제시한다. 비교 가능한 실제 시안을 통해 사용자 취향이나 양식 해석이 필요한 선택을 확인한다. 파일럿 네 종류가 기준을 통과한 뒤 전체19종으로 확장한다.

## 비교 실험과 편집 합격 기준

### 같은 내용의 재현과 새 입력의 적용을 모두 확인

첫 비교는 참고자료의 대표 텍스트·표 데이터·이미지와 같은 내용을 사용해 내용량 차이를 통제한다. 프로젝트 로컬 사본에 한정하고, 재현 실험이라는 표시와 필요한 가림 처리는 비교하는 양쪽에 동일하게 적용한다. 기존 서명·승인을 새 사업 증거로 옮기지 않는다. 의도한 변경·가림 영역과 원본 결함은 비교에서 별도 설명한다.

이어 편집 규칙을 정할 때 사용하지 않은 입력으로 적용 능력을 평가한다. 대표 문장·페이지에 맞춘 임시 조정으로 통과시키지 않는다. 짧음·보통·장문, 긴 한글명·영문 ID, 여러 문단, 값과 타입의 미확인, 계속 표, 이미지 유무를 필요한 문서군에 배분한다. 전체 조합을 무조건 생성하기보다 서식 판단이 달라지는 경계를 검증한다.

쪽수나 픽셀 일치율을 단독 합격 지표로 쓰지 않는다. 같은 의미의 제목·문단·셀·그림을 대응시켜 보고, 실제 출력의 읽기 흐름을 확인한다. 자동 좌표·폰트·폭 검사는 보조 수단이며 편집 판정을 대신하지 않는다.

| 항목 | 관찰할 합격 기준 |
|---|---|
| 폰트와 위계 | 선택한 역할별 폰트·크기·강조가 일관되고 실제 출력에 예상하지 않은 대체글꼴·누락이 없음. 제목·라벨·본문·주석을 구별할 수 있음 |
| 여백과 간격 | 선택한 구역·문단·셀의 목표값을 충족하고 같은 역할의 간격이 불규칙하지 않음. 좁은 여백을 참고에 있다는 이유로 채택하지 않음 |
| 긴 ID와 줄바꿈 | 폭·방향·표기 방식으로 먼저 해결. 필요한 분절은 정한 경계에서 일관되며 원문 ID를 임의 축약·변조하지 않음 |
| 제목과 항목 | 페이지 끝에 제목만 남지 않음. 제안 기준은 제목 뒤 본문 두 줄 또는 표 머리행과 첫 행이 함께 보이는 것. 큰 항목 전체를 무리하게 한쪽에 묶지 않음 |
| 계속 표 | 다음 쪽에서도 제목행·단위·식별자와 행/열의 대응을 알 수 있고 값이 잘리거나 다른 항목으로 오독되지 않음 |
| 공백과 밀도 | 독립 카드·표지·확인란의 의도적 공백과 고정 높이/쪽나눔 때문에 생긴 공백을 구분. 큰 공백은 역할상 이유가 있거나 수정됨 |
| 업무 표현 | 내부 JSON·디버깅 표현이 업무 본문을 대신하지 않음. 필요한 기술 정보는 읽기 좋은 명세로 남고 근거를 추적할 수 있음 |
| 그림과 설명 | 본문·번호·캡션·화면 ID가 대응하며 인쇄 크기에서 핵심 글자를 읽을 수 있음. 실제 화면과 합성 시안이 구별됨 |
| 문서 간 일관성 | 같은 사실·ID·명칭·단위·기간·상태가 문서 간에 일치하고 미확인·미수행·실제 결과가 혼동되지 않음 |

‘제목 뒤 두 줄’ 등은 이 계획의 편집 선택안이다. 모든 사업에 적용되는 공식 규정으로 저장하지 않는다. 규칙별 결과는 충족·보완·판정불가와 실제 페이지 근거로 기록한다. 임의 가중 점수로 중요한 실패를 상쇄하거나 근거 없이 ‘유사도80%’를 선언하지 않는다.

### 그림과 실제 증거의 경계

그림 처리 기능은 출처가 있는 참고 이미지와, 문서 안에 ‘합성 시안·실제 실행화면 아님’을 명시한 시험 그림으로 검증할 수 있다. 합성 사실과 그림의 필드·버튼·화살표·설명을 맞춘다. 이 검증을 통과해도 실제 구현 화면 일치·실제 수행·서명·승인 판정은 하지 않는다. 필요한 실제 자료가 없으면 해당 내용의 완성도는 보류하며 완성 문서로 보고하지 않는다.

## 전체19종 확장과 스킬 반영

파일럿 외의15종은 다음 묶음으로 확장한다. 한 문서의 변경을 모든 문서에 적용하지 않고 각 역할의 선택 프로필과 현재 출력 근거를 남긴다.

- AD1·TD1·TD2: 업무 설명과 흐름도·시스템 구성도의 결합.
- AD3·TD4: 기능 목록·프로그램 명세·관련 테이블과 긴 값 처리.
- CD1·TI1·TI2·TI3·TI4: 시험·설치/전환·사용자 안내의 내용과 증거 구분, 표·그림·절차 표현.
- OS1·OS2·PM1·PM2·PM3: 지원·운영·보고·회의·변경의 문체, 기간·상태와 관리표 배치.

OS1에는 직접 대응하는 참고가 없으므로 인접 문서의 유효한 공통 서식을 활용하되 별도 설계 근거로 평가한다. PM1의 월간 양식과 주간 참고자료는 부분 대응이다. 주간 내용을 월간 실적으로 바꾸지 않으며 같은 역할의 직접 재현이라고 보고하지 않는다.

검증된 규칙은 다음 책임에 나누어 반영한다.

| 위치 | 반영 내용 |
|---|---|
| 공통 HWPX 처리 | local 서식 정의 해결·의도한 범위 편집·구역/표/그림 연결·보존과 저장 검증 |
| 원본별/선택 서식 프로필 | 해당 양식·참고에 연결한 목표 서식·적용 조건·허용 변경·예외·검토 상태 |
| 공통 사업 사실 | 전체 입력값·타입·출처·상태와 문서 간 연결. 보기 좋게 만들기 위해 값을 바꾸지 않음 |
| 도메인 작성 지침 | 업무 문장·요약·절차·명세·근거 배치와 자료 부족 시 처리 |
| 품질 게이트 | 의미 보존·서식 적합성·실제 native 출력·전쪽 편집 검토·내용 완성 여부를 별도 판정 |

마지막에는 구현에 참여하지 않은 검토자가 설치된 스킬, 고정한 저장소 버전과 선언된 실행환경, 필요한 원본 사본·선택 프로필·첨부·미사용 입력으로 실제 문서를 만든다. 저장소 밖의 cwd에서 실행하고 원본 경로·도구·한컴 버전·글꼴 같은 의존 자원을 명시한다. 스킬 폴더만으로 전체 코드와 native 엔진이 포함된다고 가정하지 않는다. 작성자가 사용한 정답·임시 조정 내역이나 선언하지 않은 경로에 의존하지 않는다. 생성 결과의 폰트·줄바꿈·본문 표현·필드 보존·이미지를 실제로 평가하고 발견한 문제를 다시 프로필·도구·지침에 반영한다.

## 완료 판단과 최종 보고

업그레이드 완료는 다음 결과가 모두 갖춰졌을 때 판단한다.

1. 전체19종에 대해 기준·선택 프로필·적용 결과·예외가 있으며, 파일럿만으로 전체 완료를 선언하지 않는다.
2. 같은 내용 비교와 미사용 입력 모두에서 합의한 편집 기준을 충족한다. 필수 정보와 의미 필드의 누락·왜곡이 없어야 한다.
3. 의도한 서식 변경과 보존 대상이 분리되어 있고, 허용하지 않은 변화가 없다.
4. 최종 현재 바이트를 실제 한컴에서 열고 저장·재열기해 PDF로 출력한 뒤 전쪽 원본 이미지로 검토한다. 실제 버전, 원본/입력/프로필/HWPX/PDF/PNG의 해시, 검토 범위를 유지한다. 복원이 필요하면 저장 중간물과 복원 최종물을 구분한다.
5. 구조·내용 보존·native 출력·편집 적합성·자료 충족 여부를 각각 보고한다. 필수 그림·사업 사실이 없거나 미검토인 항목을 통과로 채우지 않는다. 실제 제출 가능성은 별도 판단한다.
6. 설치 스킬·고정 저장소/실행환경·명시된 원본 사본/프로필/첨부·미사용 입력으로 독립 재현이 가능하고, 규칙이 한 사례의 특정 문장·쪽수·개체 개수에 과도하게 맞춰져 있지 않다.

최종 보고에는 참고/기존/개선본 비교, 규칙의 채택·제외 사유,19종의 항목별 판정표, 독립 재현 결과와 남은 한계를 포함한다. 현재의 `reviewed-suite`와 과거 검증 기록은 기준선으로 보존하며, 개선 후보와 새 검토본은 별도 경로에 만든다.
